# Upstream provenance and coverage

The baseline uses the official [MarWaltz/TUD_RL repository](https://github.com/MarWaltz/TUD_RL) and pins source acquisition to immutable commits. `bootstrap.ps1` downloads GitHub codeload archives at those commits, expands them inside this baseline directory, and copies into a snapshot directory only when that directory is absent. Existing snapshot directories are reported and skipped; the script never overwrites them and never creates nested Git repositories.

| local snapshot | commit | codeload source | intended role |
|---|---|---|---|
| `upstream/` | `92a34ba703a5ec8c8bcad2503653dc12b971854b` | `https://codeload.github.com/MarWaltz/TUD_RL/zip/92a34ba703a5ec8c8bcad2503653dc12b971854b` | current main source snapshot |
| `upstream_dev/` | `2395f35438571e274dcb233b4cdf4f7d692ff798` | `https://codeload.github.com/MarWaltz/TUD_RL/zip/2395f35438571e274dcb233b4cdf4f7d692ff798` | dev UAM environment and validation snapshot |

The local wrapper imports UAM source from `upstream_dev`, while the raw source directories remain unchanged. The dev snapshot contains `tud_rl/envs/_envs/UAM_Modular_Validation.py`, including `entry_check` and `noise`, and `tud_rl/common/uam_scenario_eval.py`. The local four-cluster Poisson scenario (`0/120/240/360 s`, independent `Poisson(λ=5)` counts, adjacent-aircraft spacing `10 s`) is a scenario extension in `runner.py`; it is not claimed as an original TUD_RL generator.

The legacy OpenAP data used by the source performance model is pinned separately to BlueSky commit `f1626f99623c1ac20eadce0acaf930cb66842848` (2024-07-31 10:01:34 UTC). `bootstrap.ps1` reads the exact recursive GitHub tree, selects the 22 blobs under `bluesky/resources/performance/OpenAP/` plus the root `LICENSE`, and preserves them under `assets/openap_legacy/`. It copies only absent files, validates the required `engines.csv`, `aircraft.json`, `dragpolar.csv`, `rotor/aircraft.json`, and `synonym.dat` paths, and validates the expected 23 files and 165,964 total bytes. The asset `LICENSE` is retained verbatim; no MIT or other license grant is inferred.

The source implementation uses North/East coordinates and heading `0°` at North with clockwise increase. Current project logs use East/North (`x=e, y=n`); a common-physics-backend adapter must perform and test the project-frame conversion later. The source `spawn_radius=1000` is a spawn/observation-normalization parameter, not a hard circular `R=800` boundary. The paper profile keeps physical spawn radius `800` while retaining observation distance scale `1000`; this wrapper configuration must not be confused with the intact upstream implementation. The source history, NaN padding, ghost-neighbor placeholder, and own/neighbor observation semantics remain the reference inputs.

The nine `diagnostic-zero` cases (`wave_upstream`, `study30_off`, `study30_on`, `study5_noise10`, `study5_noise20`, `study5_noise100`, `poisson_off`, `poisson_on`, and `wave_paper800`) all exited 0, with `complete=true`, `truncated=false`, `active=0`, `unspawned=0`, request/spawn conservation, unique `(time,uid)` CSV rows, and `sigma∈{-1,+1}`; each produced output and a chart. These constant-zero-heading outputs are `status=runtime_diagnostic`, `policy_verified=false`, and `official_policy_claim=false`; `complete` means finite scheduling was consumed with no active vehicle and does not certify service completion, landing success, safety, or performance. No Poisson process generator or Crazyswarm2 UAM field controller was found in the retained main/dev source snapshots or in the separately inspected v1.1 release (whose assets were not downloaded). No confirmed UAM-specific actor weights are available. The seven `.pth` binaries present in the dev snapshot are other-environment artifacts (`3007_actor`, `3007_critic`, `7_plan_actor`, `7_plan_critic`, `8_follow_actor`, `8_follow_critic`, and `cpa_weights_10_1200`) and are not treated as UAM weights.

Consequently, the paper learning curve, four trained policy comparisons, and the paper's five-Crazyflie/MOCAP/Crazyswarm2 deployment cannot be reproduced from the currently available files. `CrazyflySimple` and `CrazyflyCircle` are separate Bullet/Crazyflie simulations and are not the paper's field controller. These are coverage observations only; no performance or reproduction result is claimed.

The TUD_RL snapshots contain no `LICENSE` file in the acquired trees. This records an observed repository state and assigns no open-source grant. Downloaded snapshots and asset data remain locally ignored rather than redistributed. The only legacy asset acquisition implemented here is the pinned BlueSky OpenAP subtree described above; unrelated binaries and field-controller assets remain out of scope.
