## 共同执行规则

全部方法继承阶段1固定三环、路径、容量、保护间隔、能耗、储备、外部准入及应急语义。普通意图仍选择各访问环的额外整圈等待，构成完整向内路线。联合批次必须由独立可行性层原子检查：选中路线两两兼容，保留已承诺计划，并让未选、未预约飞机继续保持。整批失败或未知时不得部分提交成不同决策。

应急沿用同一正常可行域资格检查。正常搜索被预算截断或连续安全未获证明只代表未知，不授权应急；不存在方法专属的低 SOC 阈值应急捷径。

## 六种方法

| 标识 | 调度依据与边界 |
|---|---|
| `fcfs` | 按请求到达时刻排序，随后通过共同可行性选择普通路线 |
| `soc` | 按当前 SOC 排序，保留与到达时间/ID相关的确定性平局处理 |
| `energy_slack` | 当前 SOC 减去当前预测下最低可行正常路径耗能及储备；未经极值证明时，标明仅已知界限/未知 |
| `deadline_slack` | 最后可行正常完成窗口减当前时间；未经极值证明时不得称为精确最后窗口 |
| `joint_window` | 从多机候选完整窗口中选择真正相容的一组，包含主动不选某机的可能 |
| `rolling_horizon` | 用可观测当前状态推进模拟，比较后续窗口及 HOLD/延后分支，仅承诺首批完整路线 |

规则优先级不是独立于可行性的自由动作。能源余量不能使用不可行的零等待路线下界替代真实可行最小值；deadline 不是仅用 SOC/保持能耗得到的寿命阈值。分析使用共享256次检查预算，最低可行能源按总圈数升序、最晚完成窗口按总圈数降序寻找并认证。`minimum_status` 区分 exact/upper_bound，`deadline_status` 区分 exact/lower_bound，未知或证明不可行不造数。排序先处理有已知可行精确/界限量的飞机，再处理缺少量的飞机；按指标升序，平局用到达时刻和ID。SOC规则平局同样用到达时刻和ID，FCFS用到达时刻和ID。

joint目标按字典序最大化：240 s前完成普通计划数、这些计划延迟总和的负值、全部选中计划能耗的负值。候选批次带HOLD/不选项；6架cohort、每架24生成/6保留和beam64的限制均保留截断信息；joint完全平分时按 `(ID, wait_cycles)` 元组的反序确定，HOLD分支显式保留。

## 可观测信息

可使用已经到达的飞机位置、SOC、资源预约和当前时间。生成器预采样的 `pending` 未来请求不得进入方法评分、仿真或 rollout 状态。滚动方法只对当前可观测状态进行假设推进，不具有未来到达的全知信息。完整路线一经承诺保持既有预约语义，不在滚动决策中任意撤销。滚动评分依次最大化能源失败数的负值、240 s前已完成/承诺正常数、应急激活数的负值、20 s推进末观测暴露的负值、正常延迟总和的负值、已承诺路线耗能的负值；只预测20 s，之后的承诺价值是代理量。

## 有限目录参考

小规模 oracle 采用 SciPy `optimize.milp`。固定输入候选目录后，各方法与 MILP 使用相同选择域；所有输出按共同目录字典序目标重算差距。规则仍按各自优先级选择，rolling仍按其冻结surrogate选根，不要求内部优化目标相同。返回解须独立经过可行性与共同评价目标重算。只有求解器证明有限模型最优且独立检查通过，才标记 `OPTIMAL`；时间/节点等预算受限必须保留状态和界限。目录被截断时，最优性仅限于该目录。

oracle 采用闭合 N=3/4/5/6 初态，不与持续到达的完整 rollout 指标混合。任何目录最优差距不构成全动态调度全局差距。
