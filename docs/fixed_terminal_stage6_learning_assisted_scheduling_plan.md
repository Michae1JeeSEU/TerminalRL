# 固定多环终端区联合到达调度研究重构计划：阶段6

## 阶段5审查结论

阶段5完成了学习方法必要性的严格验证。

主要结论：

1.  学习模型存在离线候选筛选能力。
2.  但尚未证明学习能够带来无损质量提升和明显计算降低。
3.  当前学习方法不能替代beam/full search。
4.  学习最有价值的方向仍然是搜索加速，而不是端到端调度。

因此阶段6目标：

# 学习辅助联合调度框架验证

重点回答：

> 学习是否能够在严格计算预算下减少传统搜索成本，同时保持系统性能。

------------------------------------------------------------------------

# 阶段6原则

继续禁止：

-   PPO
-   多智能体RL
-   teacher imitation
-   端到端动作输出
-   安全规则学习

学习模块只负责：

-   候选筛选
-   搜索排序
-   价值估计

最终决策必须经过确定性验证。

------------------------------------------------------------------------

# Step 6.1 重新定义比较目标

阶段5已经证明：

单纯提高best-key保留率不足。

因此阶段6不优化：

-   top-k accuracy

而优化：

## 固定质量约束下的计算减少

例如：

在：

正常完成率 \>= beam/full - ε

条件下：

比较：

-   精确rollout数量；
-   总计算时间；
-   搜索规模。

------------------------------------------------------------------------

# Step 6.2 建立真正公平的计算预算实验

统一：

-   同一候选池；
-   同一状态；
-   同一验证器；
-   同一CPU环境。

比较：

## baseline

-   beam B3/B5/B8
-   full reference

## learning assisted

-   rank + verification
-   GB + verification
-   hybrid

记录：

-   保留最佳比例；
-   最终J；
-   rollout数量；
-   时间。

------------------------------------------------------------------------

# Step 6.3 优先优化候选筛选，而不是价值预测

阶段5结果：

value明显弱于rank。

因此暂时不扩大value路线。

优先研究：

## 学习排序器

目标：

减少：

需要精确验证的候选数量。

流程：

候选池

↓

学习排序

↓

选择top-k

↓

精确验证

↓

fallback beam

------------------------------------------------------------------------

# Step 6.4 建立安全fallback机制

学习方法不能导致：

-   能源失败；
-   不可执行方案。

设计：

如果学习筛选失败：

自动扩大候选：

B3 → B5 → B8 → full

研究问题：

学习平均减少多少搜索，同时保持鲁棒。

------------------------------------------------------------------------

# Step 6.5 研究泛化

测试：

## SOC变化

低、中、高SOC。

## 负载变化

低、中、高负载。

## 初始状态变化

不同初始占用。

目标：

判断学习是否只是记忆固定场景。
