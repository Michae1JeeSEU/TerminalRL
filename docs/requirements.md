# 项目需求文档

## 项目概述

低空交通领域终端区降落动态空域构型与无人机控制协同的层次强化学习决策方法研究。

**核心思想**：将终端区降落问题建模为两层决策——高层负责空域构型（慢决策，~30min），低层负责无人机飞行控制（快决策，秒级），通过层次强化学习实现协同优化。

---

## 1. 空域结构

### 1.1 三层环形终端区

```
         ┌──────────────────────┐
         │    外环 (Ring 1)      │  ← 进入终端区
         │  ┌────────────────┐  │
         │  │ 中环 (Ring 2)   │  │  ← 过渡层
         │  │  ┌──────────┐  │  │
         │  │  │内环(Ring3)│  │  │  ← 降落层
         │  │  │  [降落区]  │  │  │
         │  │  └──────────┘  │  │
         │  └────────────────┘  │
         └──────────────────────┘
```

### 1.2 环间硬约束

| 约束 | 条件 |
|------|------|
| 半径 | R1 > R2 > R3（外环 > 中环 > 内环） |
| 高度 | H1 > H2 > H3（外环 > 中环 > 内环） |

硬约束在动作空间层面即施加，不允许违反。

---

## 2. 决策层级

### 2.1 高层决策（空域构型，~30分钟/次）

| 决策变量 | 类型 | 取值范围 | 维度 |
|----------|------|----------|------|
| 环半径 (R1,R2,R3) | 连续 | 受硬约束限制 | 3 |
| 环高度 (H1,H2,H3) | 连续 | 受硬约束限制 | 3 |
| 环速度 (V1,V2,V3) | 连续 | V_min ~ V_max | 3 |
| **合计** | | | **9维连续** |

### 2.2 低层决策（UAV 控制，秒级）

| 动作 | 类型 | 说明 |
|------|------|------|
| 盘旋 (Circle) | 离散 | 在当前环上沿环飞行等待 |
| 悬停 (Hover) | 离散 | 空中定点悬停等待 |
| 下降 (Descend) | 离散 + 连续参数 | 向内层环下降，附带路径点序列 |

#### 下降路径点序列

下降时附加连续参数：路径点序列，定义从当前环位置下降到内环的轨迹。每个路径点含：
- 水平坐标 (x, y)
- 高度 z
- （可选）航向角 θ

路径点数量待设计中进一步确定（建议 K=3~5 个中间点）。

### 2.3 条件动作（仅内环触发）

| 条件 | 动作 | 类型 |
|------|------|------|
| 在内环 + 决定降落 | 选择降落区域 | 离散（从 M 个备选着陆区中选择） |

降落区域为预先定义的离散备选点，数量 M 后续根据场景设定（建议 M=4~8）。

---

## 3. 优化目标（多目标协同）

| 目标 | 方向 | 含义 |
|------|------|------|
| 能耗 | 最小化 | 所有 UAV 飞行 + 等待的总能耗 |
| 等待时间 | 最小化 | UAV 进入终端区到完成降落的总耗时 |
| 系统吞吐量 | 最大化 | 单位时间内成功降落的 UAV 架次 |

多目标处理方式：加权求和或 Pareto 优化（具体方案在设计阶段确定）。

---

## 4. 约束条件

| 约束 | 类型 | 说明 |
|------|------|------|
| 安全间隔 | 硬约束 | UAV 之间间距 ≥ d_safe，环与环之间无冲突 |
| 任务优先级 | 混合（软约束） | 基础优先级预设 + 动态调整因子（等待时间/电量） |
| 剩余电量 | 硬约束 | 电量低于阈值时强制优先降落，电量为零视为任务失败 |

### 4.1 优先级计算

```
Priority = base_priority × f(wait_time) × g(battery_ratio)
```

- base_priority：任务类型预设值（医疗急救=5, 物流=3, 巡检=1）
- f(wait_time)：等待超时升级因子
- g(battery_ratio)：电量衰减升级因子

## 5. UAV 规模路线

| 阶段 | 规模 | 任务 |
|------|------|------|
| Phase 3-5 | 5-20 架 | 单/少 UAV 开发调试 |

| Phase 7 | >200 架 | 大规模扩展，分布式决策 |

## 6. UAV 初始状态分布

仿真开始时，UAV 分布在三个环中（非全部在环1边界）：
- 环 1 (外环): ~50% 的 UAV，位置在环1体积内 (R2 < r ≤ R1, H2 < z ≤ H1)
- 环 2 (中环): ~30% 的 UAV，位置在环2体积内 (R3 < r ≤ R2, H3 < z ≤ H2)
- 环 3 (内环): ~20% 的 UAV，位置在环3体积内 (0 < r ≤ R3, 0 < z ≤ H3)

每架 UAV 初始状态随机化：
- **位置**：通过 `random_position_in_ring()` 在所属环体积内均匀随机采样
- **电量**：在 battery_critical × max_battery ~ max_battery 之间均匀随机
- **等待时间**：在 0 ~ 600 秒之间均匀随机
- **状态**：根据所在环按概率分布分配
  - 环1: 80% CRUISING, 20% HOLDING
  - 环2: 40% CRUISING, 30% HOLDING, 30% DESCENDING
  - 环3: 40% HOLDING, 60% DESCENDING
- **基础优先级**：按 {1:50%, 3:35%, 5:15%} 概率随机分配

**替换生成**：当 UAV 着陆后，在环1边界生成新 UAV 作为新进入终端区的无人机，状态同样随机化。

## 7. 仿真环境

- 基于 OpenAI Gymnasium 接口的自定义环境
- 纯数值仿真（无物理引擎）
- 支持：reset / step / render 标准接口
- 可配置：UAV 数量、环初始参数、降落区域数量

---

## 8. 层次强化学习框架

- 架构：Options 框架（Call-and-Return）
- 高层 policy：选 option（空域参数），每 ~30min 调用一次
- 低层 policy：在 option 约束下执行 UAV 控制动作，秒级调用
- 扩展方向：大规模时低层可分布式执行
