# 固定多环终端区联合到达调度研究重构计划：阶段3

## 阶段2审查结论

阶段2完成了传统方法性能边界分析，核心结论：

1.  固定终端区问题已经可以被传统调度方法稳定求解，安全约束不是主要瓶颈。
2.  简单优先级方法（FCFS、SOC、energy slack、deadline
    slack）不能稳定改善系统性能。
3.  真正有效的改进来自考虑联合可行性的调度：
    -   joint_window
    -   rolling_horizon
4.  传统方法仍存在两个明显不足：
    -   在线计算成本随复杂度增长；
    -   对长期交通影响的估计有限。

因此，下一阶段不直接训练RL，而是进入：

# 阶段3：联合调度问题机制分析与学习问题定义

目标：

回答：

> 如果未来引入学习方法，它到底应该学习什么？

# 阶段3总体任务

## Step 3.1 分析传统方法失败模式

目标：

从结果中找到学习价值来源。

重点分析：

### 1. 为什么priority失败？

比较：

-   FCFS
-   SOC
-   energy slack
-   deadline slack

分析：

是否存在：

-   单机紧迫性不足；
-   多机资源竞争；
-   后续影响。

------------------------------------------------------------------------

### 2. 为什么joint/rolling有效？

分析：

joint和rolling做出了哪些不同决策：

-   谁被提前释放；
-   谁主动等待；
-   哪些决策减少后续阻塞。

建立：

调度决策解释数据库。

------------------------------------------------------------------------

# Step 3.2 建立调度价值定义

目标：

从人工priority转向系统价值。

定义候选动作：

a_i

表示：

给某架飞机某个服务窗口。

定义：

长期收益：

ΔJ(a_i)

例如：

-   正常完成增加；
-   应急减少；
-   总延迟降低；
-   能耗降低。

重点：

学习对象不是：

"谁最紧急"。

而是：

"当前调度机会对整个系统未来价值"。

------------------------------------------------------------------------

# Step 3.3 建立强传统参考求解器

目标：

形成未来学习方法的参照。

扩展rolling：

增加：

-   更长预测窗口；
-   更丰富候选；
-   更强搜索。

用途：

不是部署。

用于产生高质量参考。

------------------------------------------------------------------------

# Step 3.4 判断学习是否必要

根据实验结果决定路线。

## 情况A

强传统方法已经很好：

研究重点转向：

-   快速求解；
-   分布式优化。

------------------------------------------------------------------------

## 情况B

传统方法性能好但计算慢：

学习方向：

> 学习快速近似调度器。

------------------------------------------------------------------------

## 情况C

传统方法无法捕获长期影响：

学习方向：

> 学习长期价值函数。
