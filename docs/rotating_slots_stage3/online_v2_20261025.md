The network remains the 119,555-parameter, 66-query-dimension, three-head set MLP. One formal training guard permits seed20261023, at most30 epochs and patience5. There is no RL, value learning, architecture expansion or solver-budget increase.

Source changes and Git operations stay local.

`scripts/stage3/run_online_v2.py` reuses the existing CampaignLedger and subprocess watchdog. Its explicit stages are `freeze`, `prepare`, `tests`, `collect`, `repair-pretrain`, `train`, `dev`, `evaluate` and `archive`. There is no all-stages command. The original four-hour wall, 13,500-second compute stop and per-phase caps remain in force; the ledger pauses on every normal/error stage exit. Started stage guards and the model's exclusive formal-training guard persist after failure.

Preparation uses a fresh committed source freeze without a seed scan and copies the old split manifest byte for byte. Old initial checkpoint identity remains attached to the old physical input; the new model fingerprint binds actual new source, v2 feature/cost schema and online/ranking policy. V1 training/validation features migrate only their known numeric fields. Missing new context stays masked, and incomplete legacy cost targets remain masked. Original feature provenance is retained. Sealed test label files are never read for training or a new heldout-signal measurement.

Their ancestry remains s3r01/s3r02/s3r17. The H rollout uses the shared progressive catalog and light online observer. At30s an OFF scheduler's cold search state is saved with the unchanged physical world, including active commitments, soft plans and energy. The saved time is30s, never relabeled as t0. Each state then receives one bounded offline v2 feature/label collection, retaining the existing180s snapshot cap and at most8 conditional solves. At most two independent roots run concurrently, each on its own physical core with numerical threads1. These rollouts acquire training data; they are not extra online benchmarks.

Before the sole fit, training groups must contain approved ranking pairs or at least one complete v2 measured-cost target. Legacy validity-only groups remain outside training; validity loss still applies within admitted groups. Both training and validation must have ranking pairs before a formal guard is created. Checkpoint selection remains validation ranking loss. Cost diagnostics include cost-only validation groups and reuse each existing three-head prediction to report the fixed cost adjustment, observed penalties and ordering changes over the measured-cost examples only.

The explicit `repair-pretrain --source-freeze NEW_FREEZE` command repairs collected evidence references and adopts a reviewed implementation freeze without acquisition, simulation, labeling solves or fitting. It requires completed collection, a paused inactive ledger, no live or unresolved jobs, and no training/model/heldout guard. Only learning, labeling, this runner and their two scoped test files may differ between frozen execution inventories. Original binding, source freeze, protocol, dataset and index bytes are archived under `implementation_repair_pretrain`; original raw streams and labels stay untouched. `labels_reindexed` contains derived labels with intervention-qualified IDs. Pair directions/sources/counts, contribution masks/values and dataset numeric contents must match the originals. The new binding and protocol identify the actual execution freeze, while nested collection provenance retains the original source and fingerprint. Repair wall time is credited to the existing data-and-labels phase without resetting the ledger. An immutable repair receipt records the before/after hashes and training-group counts. A prior repair attempt blocks retries for primary review.

Development uses exactly two explicit root/checkpoint specs. The provisional pair is original s3r23:t0 and the encoding archive's H s3r23 `checkpoint_0030.json`. Local inspection found time0/30 respectively and `sink=null` for both. The original t0 checkpoint stays byte-identical. The old H checkpoint contains a GUIDED_LIMITED scheduler binding and cannot load into the paired experiment's OFF cold restore. For this30s development input only, the runner archives original bytes as `source.checkpoint.json`, replaces only the encoded scheduler with a fresh OFF search state, and recomputes the envelope digest. A canonical digest asserts that **every other payload field** remains unchanged, including the complete encoded world, identity, time, sink and boundary summary. This is a paired cold-cache development comparison, not a continuation of the old search process. `initial_state.json` and its hash come from the actual restored30s physical world; the original root's t0 hash and raw checkpoint SHA remain separate provenance. A nonnull sink requires returning to the primary agent for an explicit stream-copy restore. No Stage1 seed71 checkpoint is assumed compatible.

Each development state receives original bounded-catalog reference, progressive H, and progressive L: six callback jobs total. All three use candidate6s/32 per-aircraft/1,024 attempts, hint3s, CP8s, soft30s and watchdog60s, CPU12 serial, fresh process, light telemetry and the same prefix memo. Reference disables progressive catalog expansion only; its result is bounded evidence, not a global optimum. L changes ordering with the fixed0.1 normalized predicted log-cost term. Development reports callback/full job cost, actual P50/P95/max, candidate rounds, CP/validation/prefix reuse, learned rank/cache activity and bounded-reference quality comparisons. Both states are `DEVELOPMENT_SEEN`; they support no independent generalization claim.

The new candidate6s limit counts cumulative **active candidate work**, including candidate generation and attributable single-column validation; selection time is excluded. The old single-catalog implementation used elapsed candidate-clock time. Historical timing comparisons therefore remain descriptive. New H/L use the same active-clock definition and caps. The fixed0.1 cost penalty uses normalization fitted from training cost targets only. Targets sum actually measured generator, energy and attributable validation work; missing components and ambiguous contribution counterfactuals remain masked. CP wall time is never allocated to individual candidates. The two bounded reference callbacks can reveal missed better solutions in their observed catalogs; they cannot exhaustively detect quality loss.

The primary agent must review completed development results before invoking `evaluate --reviewed-dev`. Formal closed-loop comparison is exactly H then L on original s3r23(seed7324), one60s window each, physical CPU12 serial, no profiler or renderer. Five-second completed boundaries are retained. Quality differences use the last completed boundary shared by H and L, with terminal observations reported separately. The ReplayBundle retains authoritative world states, events and committed plans; aggregate online counters replace raw feature arrays. No quality degradation tolerance is authorized.
