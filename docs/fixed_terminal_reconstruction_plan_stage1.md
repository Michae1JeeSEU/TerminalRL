# 固定多环终端区联合到达调度研究重构总体方案（阶段化版本）

## 研究主线

本研究只关注第一个研究问题：

> 固定多环终端区内，在随机剩余电量（SOC）与安全间隔约束下，对跨环转移、最后进近和着陆资源进行联合调度，提高正常着陆效率，并控制应急着陆代价。

暂不研究动态空域调整、动态环半径、高度重构或自由三维空域。

核心研究对象不是单机路径规划，而是**有限空间资源条件下的多机协同到达调度问题**。

------------------------------------------------------------------------

# 总体研究原则

## 1. 不预设算法形式

研究过程不预设必须使用强化学习，也不预设 teacher。

需要先回答：

1.  固定多环终端区在目标运行域下是否存在高效调度机制？
2.  传统优化和启发式方法能够达到什么水平？
3.  剩余性能差距是否来自难以在线计算的长期影响？
4.  学习方法是否能够以更低在线成本逼近或超过传统方法？

------------------------------------------------------------------------

## 2. 安全、能源可行性与调度决策分层

系统划分为三个层次：

### 可行性层

负责：

-   安全间隔；
-   轨迹可执行性；
-   环容量；
-   跨环转移合法性；
-   pad资源约束；
-   最低能源储备。

该层不能交给学习模型。

### 调度层

负责：

-   哪架飞机优先进入哪个窗口；
-   是否主动等待；
-   如何减少未来拥堵；
-   如何降低应急比例。

这是主要研究对象。

### 学习层（候选）

负责：

-   从状态中学习调度价值；
-   预测某个调度动作的长期影响；
-   降低在线搜索成本。

------------------------------------------------------------------------

# 总体阶段划分

## 阶段0：研究合同冻结与运行域定义

目标：

建立所有后续实验必须遵守的问题定义。

主要内容：

-   固定终端区结构；
-   明确环数量、半径、高度；
-   明确飞机运动模式；
-   明确安全间隔；
-   明确SOC模型；
-   明确pad服务模型；
-   明确容量定义；
-   明确成功、失败和应急定义。

输出：

《固定多环终端区联合调度问题定义》

------------------------------------------------------------------------

## 阶段1：建立可信仿真基础与运行域

目标：

确保研究问题本身合理。

重点：

### 场景

建立：

-   低流量；
-   中流量；
-   高流量；

三类运行强度。

高密度场景：

-   初始各环均非空；
-   各环接近运营容量；
-   存在持续进入需求。

### SOC

采用截断正态分布。

逐步增加困难：

1.  高SOC基础场景；
2.  中等随机SOC；
3.  低SOC压力场景。

### 能源

建立：

-   正常着陆最低能源；
-   应急着陆最低能源；
-   不同位置、路径对应能源需求。

输出：

可信运行域和测试场景生成器。

------------------------------------------------------------------------

## 阶段2：传统方法强基线

目标：

建立固定空域下最强非学习方法。

不是简单实现FCFS，而是针对本问题融合改进。

候选方向：

### 能源感知调度

考虑：

-   能量余量；
-   最晚可行着陆时间；
-   剩余等待能力。

### 资源预约调度

考虑：

-   环容量；
-   转移窗口；
-   最后进近窗口；
-   pad占用。

### 滚动优化方法

考虑：

-   MPC；
-   MILP/CP-SAT小规模参考；
-   滚动窗口启发式。

输出：

传统方法性能上界和瓶颈分析。

------------------------------------------------------------------------

## 阶段3：分析学习价值

目标：

判断学习是否值得加入。

重点分析：

传统方法失败来源：

-   搜索空间过大？
-   后续影响难预测？
-   计算时间过高？

如果传统方法已经接近参考解，则学习重点转向降低计算成本。

输出：

学习问题定义。

------------------------------------------------------------------------

## 阶段4：学习调度方法

目标：

设计学习型调度器。

核心思想：

学习"调度价值"，而不是学习安全规则。

可能形式：

-   图网络；
-   集合网络；
-   RL；
-   模仿学习；
-   离线强化学习。

学习对象：

不是人工定义的priority。

而是：

> 当前给予某架飞机某个服务窗口，对未来系统性能的影响。

输入：

-   当前飞机状态；
-   SOC；
-   后续可行窗口；
-   邻近交通状态；
-   资源占用。

输出：

-   候选动作评分。

------------------------------------------------------------------------

## 阶段5：信息约束研究

目标：

研究实际部署需要的信息量。

逐步减少：

1.  全局状态；
2.  区域状态；
3.  邻机和资源摘要；
4.  局部观测。

分析：

性能下降来自哪里。

------------------------------------------------------------------------

# 第一阶段详细计划

## 阶段1目标

建立一个可信、可复现、符合研究目标的固定多环终端区运行环境。

本阶段不训练学习模型。

不比较RL性能。

不追求算法创新。

重点是：

> 确保后续所有算法比较建立在正确的问题定义上。

------------------------------------------------------------------------

# Step 1.1 固定空域结构定义

确定：

-   环数量；
-   半径；
-   高度；
-   转移节点；
-   最后进近区域；
-   pad布局。

要求：

结构必须支持：

-   环内保持；
-   环间转移；
-   最终降落。

禁止：

-   动态改变结构；
-   根据算法调整容量。

------------------------------------------------------------------------

# Step 1.2 容量模型建立

分别定义：

## 几何容量

由安全间隔计算。

## 运营容量

考虑：

-   跟踪误差；
-   转移窗口；
-   并入需求。

实验报告必须区分二者。

------------------------------------------------------------------------

# Step 1.3 安全模型冻结

明确：

-   空间间隔；
-   时间间隔；
-   转移冲突规则；
-   最后进近间隔。

安全约束必须独立于调度算法。

------------------------------------------------------------------------

# Step 1.4 能源模型冻结

建立：

SOC动态：

SOC(t+dt)=SOC(t)-E(dt)

考虑：

-   环内等待；
-   环间移动；
-   下降；
-   着陆。

建立：

正常着陆能源需求：

E_normal

应急能源需求：

E_emergency

------------------------------------------------------------------------

# Step 1.5 应急定义

应急不是简单低SOC。

定义：

正常方案不存在时：

-   是否仍存在应急路径；
-   是否满足储备；
-   是否占用应急资源。

记录：

-   应急次数；
-   应急原因；
-   应急造成的额外代价。

------------------------------------------------------------------------

# Step 1.6 场景生成器

建立标准scenario。

至少包含：

## 低负载

验证基础正确性。

## 中负载

接近正常运营。

## 高负载

特点：

-   环初始占用高；
-   持续进入；
-   SOC随机。

------------------------------------------------------------------------

# Step 1.7 建立评价指标

统一：

效率：

-   平均着陆时间；
-   延迟；
-   吞吐。

能源：

-   平均耗能；
-   最低SOC；
-   应急比例。

安全：

-   间隔违反；
-   不可执行计划。

计算：

-   在线时间；
-   搜索规模。

------------------------------------------------------------------------

# 阶段1完成后的审查重点

完成后不立即进入下一阶段。

需要重新审查：

1.  场景是否真实；
2.  容量是否合理；
3.  高密度是否物理可行；
4.  能源约束是否过强或过弱；
5.  指标是否能区分方法优劣。

只有研究问题稳定后，再制定阶段2详细实施方案。

------------------------------------------------------------------------

# 当前禁止事项

在阶段1：

禁止：

-   引入RL；
-   修改空域结构；
-   优化网络结构；
-   设计teacher；
-   根据结果调整场景。

原因：

避免再次出现算法驱动问题定义的情况。
