# 固定多环终端区联合调度问题定义

状态：阶段1问题合同；2026-10-13。下述参数、容量、服务时长、候选域、环境接口和指标已按实现核对；验证进度由状态页单独记录。当前进度见[CURRENT_STATUS](CURRENT_STATUS.md)。

## 1. 研究对象与边界

固定多环终端区中，请求携带到达时刻与初始 SOC。系统联合决定各环等待、向内相邻跨环、最后进近及着陆资源窗口；目标是提高正常着陆效率并控制应急代价。几何、路径结构、安全规则和容量不随调度方法或运行结果改变。

阶段1建立问题与运行域，不比较算法，不引入 RL、IL、teacher 或动态空域。仿真是归一化能源与有界运动学的合成研究模型，尚无硬件能耗标定、真实流量拟合或实机跟踪验证。未显式建模加速度与空气动力学，因此“可执行”只覆盖声明的运动学约束。

## 2. 固定几何与参数

长度单位 m，时间单位 s，角度单位 rad，SOC 为无量纲电量比例。环索引 `0, 1, 2` 从内到外排列。

| 参数 | 已选默认值 | 解释 |
|---|---:|---|
| 环半径 | 12、20、28 m | 固定同心多环 |
| 对应高度 | 6、10、14 m | 内低外高 |
| 共同角速度 | 0.12 rad/s | 环内保持速度随半径变化 |
| 基础空间间隔 | 3 m | 轨迹间安全距离要求 |
| 单机跟踪余量 | 0.5 m | 双机保护距离为 3 + 2 × 0.5 = 4 m |
| 最大速度 | 4 m/s | 运动学轨迹界限 |
| 最大下降率 | 1 m/s | 运动学下降界限 |
| 向内转移节点角 | 0 | 相邻环向内转移 |
| 正常 pad | (0, 0, 0) m | 固定着陆资源 |
| 应急节点角 | π | 应急路径入口 |
| 应急 pad | (-38, 0, 0) m | 独立应急资源 |
| 观察窗 | 240 s | 有限时间窗统计 |
| 仿真步长 | 1 s | 不代替连续安全检查 |

令半径为 r，基础间隔 d = 3，保护距离 D = 4，角速度 ω = 0.12。几何容量为 `floor(π / asin(d / (2r)))`，对应 **25、41、58**。运营容量为 `max(0, floor(2π / (2 asin(D / (2r)) + ω (temporal_spacing + merge_window))) − merge_spare_slots)`，其中两个时间参数均为 2 s，预留 1 个并入槽，得到 **6、8、9**。运营容量是保守的研究配置，不是几何堆积上限；未来方法不能改变它。高负载初态按运营容量生成，不允许通过初始冲突制造压力。

转移速度设为 2 m/s；线性段耗时为三维距离/2 与垂直距离/1 的较大值。内环至正常 pad 上方 0.5 m 为下降段，末段以 0.5 m/s 着陆，耗时 1 s。应急先沿负 x 方向转移到应急 pad 正上方，再垂直下降与着陆。每个路径资源区间前后各扩展 1 s；并入资源在并入时刻前后各占 2 s。pad 从着陆起点前 1 s 占用至接地后 5 s 服务结束再加 1 s；接地后 5 s 内仍作为静止障碍参与间隔检查。轨迹在圆弧/直线衔接处可瞬时改变航向，不模拟加速度。

共同环周期为 `2π/0.12 ≈ 52.359878 s`。连续混合轨迹检查使用相对速度界递归细分；无法在 0.005 s 容差内证明安全时返回未知并不执行该计划。任何冻结项变更须显式记录，不得为了改善 pilot 结果调参。

## 3. 运动与独立可行性

飞行模式至少区分环内保持、相邻向内转移、下降进近、着陆；外部准入前等待及应急运动的几何/能耗边界须明确。普通计划顺序向内，不跳环、不反向转移，不修改几何。

联合计划必须能够选择中间环的等待窗口以及后续转移、进近和 pad 时间。可行性层独立验证：

- 连续轨迹间隔，包括仿真采样点之间及路径衔接附近；
- 速度、下降率和模型已声明的路径约束；
- 环运营容量、合法转移与并入窗口；
- 最后进近时间间隔和 pad 服务占用；
- 计划路径和等待的能源消耗及到达时最低储备。

几何上无碰撞不等于资源可行；有空闲 pad 也不等于能源可达。任一约束失败均不得执行正常计划。所有未来调度方法共用同一可行性规则。

## 4. 归一化能源模型

对运动模式 m，`SOC(t+Δt) = SOC(t) − rate_m × Δt`。分段轨迹累计全部运动与等待时长；最低着陆储备为 0.06。

| 模式 | 消耗率（SOC/s） |
|---|---:|
| 环内保持 | 0.0008 |
| 跨环转移 | 0.0012 |
| 下降 | 0.0009 |
| 着陆 | 0.0014 |

下降的跨环转移同时计转移与下降消耗，即 0.0021 SOC/s；同高应急外移计转移消耗，应急垂降计下降消耗。正常与应急均计末段着陆消耗。接地后 pad 地面服务不再扣飞行 SOC，但继续占用资源并参与安全检查。

正常所需能源由当前状态及具体联合计划决定，包含窗口等待；应急所需能源由实际应急路线决定。`required_energy` 返回路径耗能加 0.06 储备，不能用单一 SOC 阈值替代。外部等待采用环内保持的 0.0008 SOC/s 消耗率，从实际请求时刻开始计量。

## 5. 正常、应急、失败与未知

正常可行性针对已承诺预约和其他未预约飞机持续环内保持的预测。它不是允许所有飞机重新调度后仍不可能正常着陆的证明。

若当前位于环 k，则正常意图为 `wait_cycles=(c0,…,ck)`，每项为对应环离环前额外等待的完整圈数。当前位置先到节点角 0，随后按选定圈数等待并依次向内；每个中间环可独立选择等待圈数。设零额外圈路径能耗为 E0，当前 SOC 为 S，单圈能耗为 `lap_time × hold_rate`，则候选域为所有非负整数向量且 `sum(ci) ≤ floor((S − reserve − E0) / (lap_time × hold_rate))`。若分子为负，正常域在能源上为空。按总圈数由小到大枚举全部组合。

该有限域由 SOC 而非 240 s 观察窗限制，允许计划在观察窗之后完成。它是固定节点、整圈等待和当前交通预测下的模型候选域，不是连续时间任意轨迹的全局可行性证明。

只有完整检查此域且正常可行集为空，才允许请求应急。应急还必须具有可达路径、满足最低储备并能预约应急资源。低 SOC、启发式排序失败或达到搜索次数上限均不足以触发此结论。若正常域未被穷尽，结果是“未知”，不能记作已证明的正常不可行。

正常着陆、应急着陆、明确失败和观察窗结束时尚未完成的截尾互斥。应急原因、实际应急路径耗能与应急资源秒数须保留；这些是物理消耗指标，不是对其他飞机造成影响的反事实因果代价。无法应急的请求不得消失。可行性返回 `feasible / infeasible / unknown` 及原因；`search_limit` 和 `uncertified_candidates` 只产生未知，完整否定原因包括 `all_normal_routes_exceed_energy` 或 `normal_domain_exhausted`。环境结局字段为 `normal_landed / emergency_landed / failed_energy / censored`。其中 SOC 耗尽为吸收失败；未预约保持/外部等待的耗尽时刻按步内剩余 SOC/保持消耗率精确记录，状态在该步处理时转入失败，连续安全监视仍保守检查完整末步。失败后的坠落与恢复运动不在本模型内。

## 6. 场景与外部需求

负载和 SOC 是独立因素，使用相互独立且固定种子的随机流。固定需求种子时改变 SOC 参数不应改变到达时刻；不以全局随机数生成器的调用顺序隐式耦合两者。

| 负载 | 到达间隔尺度 |
|---|---:|
| 低 | 35 s |
| 中 | 18 s |
| 高 | 8 s |

到达间隔采用对应均值的指数分布，生成时刻严格小于观察窗的外部请求。各环初始数量为 `max(1, ceil(运营容量 × initial_fraction))`；低、中、高占用比例为 0.25、0.6、0.9，对应数量 **(2,2,3)、(4,5,6)、(6,8,9)**。高负载因此初始各环达到本模型运营容量，随后持续产生外部请求。初始相位均匀分布并带固定 0.37 槽偏移，场景生成检查所有初始飞机的 4 m 保护距离。

标准种子为 **101、202、303**；`stream_seed(seed, "demand")` 与 `stream_seed(seed, "soc")` 从独立命名派生两个随机流。

| SOC 情景 | 正态均值 | 标准差 | 截断区间 |
|---|---:|---:|---|
| 高 | 0.85 | 0.08 | [0.05, 0.98] |
| 中 | 0.55 | 0.12 | [0.05, 0.98] |
| 低 | 0.30 | 0.10 | [0.05, 0.98] |

SOC 使用拒绝采样：抽样落在区间外时重新抽样，而非把越界值裁剪到端点。到达与 SOC 各自可复现，完整保存实际种子及配置。

请求从产生时刻即属于系统统计。外部队列是抽象边界等待，不模拟外部空间轨迹，也不宣称验证外部防碰撞。外部等待按 0.0008 SOC/s 扣能耗；SOC 耗尽记为 `failed_energy`，不隐去请求。准入仅发生在外环角 0 节点。首先计算从该节点出发、零额外整圈的正常与应急路径耗能加储备，若当前 SOC 低于两者较小值则继续外部等待，记录 `minimum_route_energy_reserve`；这项能源下界检查不授权应急，也不保证已有可预约路线。随后检查候选保持轨迹相对于所有已承诺完整计划及其他保持飞机的连续安全和环容量。检查期至少为一整圈，且覆盖现有计划接地后 pad 服务结束；无法证明安全时继续外部等待。

环境以 1 s 步长尝试准入，分数时刻产生的请求在后续准入检查时才可进入，但从原始到达时刻累计等待和能耗。初始飞机 `arrival_time=admitted_time=0`。观察窗结束仍未完成的飞机记为 `censored`，通过 `state_at_cutoff` 区分外部积压、环内保持和已预约但尚未接地。

## 7. 指标口径

总请求分母包含初始飞机与观察窗内产生的全部外部请求。明确区分初始飞机的观察起点和后续请求的产生时刻。完整观察窗结束时满足计数闭合：总请求 = 正常 + 应急 + 失败 + 截尾。中间报告把尚未到达请求单列 `not_arrived`，此时闭合式额外包含该项，`arrived_request_count` 只计已到达请求。

| 指标组 | 必须报告的内容 |
|---|---|
| 结局 | 全请求数、正常/应急/失败/截尾数及比例；失败/应急原因；外部积压 |
| 效率 | 正常吞吐；到达至准入与完成的时间；全请求已观察在系统时长；完成子集延迟和样本数 |
| 能源 | 全请求已观察消耗、最低 SOC、正常与应急路径耗能；未完成请求已发生消耗仍纳入 |
| 应急代价 | 应急次数/原因、计划路径耗能和各应急资源预约区间并集秒数 |
| 安全与执行 | 连续间隔违反、不可执行计划、容量/资源冲突及被拒绝计划 |
| 计算 | 在线时间、候选/搜索规模、未知正常可行性次数 |

请求级 `observed_request_seconds = max(0, min(当前时刻, 终止时刻) − arrival_time)`；未终止则使用当前时刻。它包含已经观察到的等待和飞行，不是完整着陆时间。`energy_consumed_soc` 包含失败与截尾前已经消耗的能源；`energy_mean_soc_all_requests` 的分母为所有请求，`energy_mean_soc_arrived_requests` 仅以当前已到达请求计；完整观察窗二者分母相同。`observed_request_exposure_seconds` 为全请求已观察在系统时长之和。`state_at_cutoff_counts` 和 `censored_state_counts` 区分外部、保持和已预约积压；`admission_rejection_counts` 记录能源、容量与间隔等准入拒绝的检查次数，同一请求可重复计数。

仅已着陆请求具有 `landing_duration_seconds = completion_time − arrival_time` 和 `delay_seconds = landing_duration_seconds − unimpeded_duration_seconds`。无阻塞基准是同一初始位置、零额外等待圈的固定正常路线；外部请求假设在产生时立即从外环节点准入。`*_conditional_landed` 汇总包含正常和应急着陆，以 `landing_metric_denominator` 标明样本数；另分别报告 `normal_landing_duration_mean_seconds`、`normal_delay_mean_seconds`、`emergency_landing_duration_mean_seconds` 与 `emergency_delay_mean_seconds_vs_normal_route`，配套各自 `*_landing_metric_denominator`。应急路径的该延迟仍相对于正常基准解释，不是应急影响的因果估计。失败与截尾的完成时间指标为 `null`，其已观察时间和能耗保留；空的平均值为 `null`。

`throughput_landings_per_second` 为全部已着陆数/观察时间；`normal_throughput_per_second` 与 `emergency_throughput_per_second` 分别按正常数和应急数除以观察时间，不能将两者混用。运行监视器 `separation_violation_pair_ticks` 计基础 3 m 间隔违反的飞机对-时间步，`spacing_uncertified_pair_ticks` 计未获证明的飞机对-时间步；提交可行性检查使用更严格的 4 m 保护距离。未知意图与明确不可行意图分开计数。

`emergency_activation_count` 计已承诺应急计划数，包括尚未着陆者；`emergency_landed` 只计已着陆者。`emergency_planned_energy_soc` 记录整个应急计划能耗，`emergency_reserved_resource_seconds` 按每个专用资源先取预约区间并集再求和，因此可包含观察窗之后的已预约部分；实际已观察消耗仍由 `energy_consumed_soc` 表示。它们不衡量对其他请求的延迟外部性。完整字段见 `metrics.py` 和[技术规范](technical_spec.md)。

## 8. 阶段1结束点

用冻结场景完成针对性测试、pilot 和运行域审查，讨论几何/运营容量、高密度可行性、能源约束强弱与指标解释。测试通过仅证明所测模型性质，不证明真实运行场景适用性。旧训练与资格认证报告保留历史用途。

阶段1结束后停止于审查；不自动开始传统方法比较或任何学习阶段。后续任务依据[总体方案](fixed_terminal_reconstruction_plan_stage1.md)另行制定。
