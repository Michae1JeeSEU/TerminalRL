## 已冻结的调度预算与目标

| 项目 | 固定设置 |
|---|---|
| 公共决策周期 | 5 s，环境 dt=1 s 不变 |
| 普通/应急与优先级分析 | 每次最多 256 次候选检查；截断输出未知/界限 |
| joint cohort | 当前保持飞机按 FCFS+ID 排序取前 6 架 |
| joint 候选 | 每架至多生成 24 个，保留至多 6 个规范普通候选 |
| joint beam | 64 |
| rolling 模拟 | 20 s，最多 4 个根分支且包含 HOLD；后续每 5 s 用 joint 继续 |
| oracle 目录 | 每架最先 4 个满足能源的普通等待向量；固定 240 s 区间 |
| oracle 总预算 | 各字典序目标阶段共享总计 30 s、1000 次求解/割迭代上限；达到预算保留受限状态 |

最低可行能源分析按总额外圈数升序；最后可行完成窗口按总圈数降序。两方向在共同 256 次检查预算内寻找并认证对应极值，未获认证只能给出已知界限/未知，不把大目录的升序前缀末端当作精确最晚窗口。

rolling 根分支的冻结评分按以下字典序最大化：`(-failed_energy_count, normal_planned_or_landed_by_240s_count, -emergency_activation_count, -observed_request_exposure_at_rollout_stop, -normal_delay_sum, -total_committed_route_energy)`。它先比较能源失败，再比较观察窗内已完成或已预约正常数、应急、20 s推进后的观测暴露、正常延迟和承诺路线耗能。20 s之后的已承诺计划仅是价值代理，不代表已经实现的未来完成或全知全局优化；未到达请求始终不可见。

oracle 是普通计划目录问题，目标依次为：最大正常数、最小正常延迟总和、最小路线总耗能；各目标阶段共享总预算。六方法的小实例结果须用完全相同目录和目标重算。完整运行指标与有限目录目标分别报告，不以oracle gap代替完整rollout差距。joint评分为 `(240s前完成的普通计划数, −这些计划的正常延迟总和, −所有已选计划总耗能)`；通过候选选择表达HOLD，未被选择的飞机保持。明确这也是有界搜索评分，不改变以上预算或物理参数。公开API见[技术规范](../technical_spec.md)。

## Oracle 闭合实例

从现有 high-load、medium-SOC 生成器的初始请求中按环轮流选取 N=3、4、5、6 架；种子同为 101、202、303，共 **12** 个闭合实例，不包含后续持续外部到达。选择规则固定，不按解质量筛选。

六方法及MILP使用同一候选目录；各自选出的结果按共同目录字典序目标评价差距。规则仍以各自优先级选择、rolling以冻结surrogate选根，不将共同评价目标误写为相同内部优化目标。报告目录是否完整、求解状态、可行解目标、可用界限、独立可行性检查和计算时间。只有有限问题得到最优证明且复核成功，才标 `OPTIMAL`；受限结果不能冒充最优。结果不能外推为完整动态问题最优性。SciPy 的 `status=0` 表示已找到最优解，`status=1` 表示迭代或时间受限；本项目还要求独立约束和目标复核，详见 [SciPy milp 官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)。

## 信息与可行性

方法只观察已到达请求及已有预约，屏蔽已采样未来 `pending` 请求。普通联合批次由独立层原子验证，未选飞机继续保持，已承诺计划不撤销。所有方法共用应急证书；搜索受限不授权应急。真实最小可行正常耗能和最后可行完成窗口在截断时保留未知或界限。

## 指标与验证

完整输出每个请求的正常、应急、失败、截尾及状态，保留全请求分母；分别报告正常吞吐、条件平均/最大延迟、耗能、最低SOC、应急资源、约束拒绝、未知、在线时间及搜索规模。完整结果schema为 `fixed-terminal-stage2-v1`；`decisions.jsonl` 保存每次候选/联合检查/优先级窗口状态/截断/计算信息。沿用阶段1观测暴露与截尾语义，详见[技术规范](../technical_spec.md)。

`generated/examined`与`joint_assignments`是累计生成/检查工作量，可能包含重复；联合检查包括放宽的部分批次与最终完整批次，不是唯一完整解数或目录容量。`oracle.candidates`才是该固定参考目录的候选数，不能据累计检查计数推断完整组合空间大小。

先通过联合批次、规则量定义、HOLD/状态推进、未来信息隔离、oracle目标与独立验证的针对性测试，再做小样本序列化 smoke。正式运行须等主审明确授权；每次运行记录真实退出码及产物，汇总独立核对计数、指标和 finite JSON。

阶段2结束后审查传统方法收益与计算代价，再讨论是否需要学习；不自动启动下一阶段。最终交付 ZIP 包含所有重要阶段2文档和全部最终结果，紧凑摘要进入版本控制。

所有耗时是本机并发运行下的实际实现计时，包含解释器启动（进程墙钟）和调度竞争，不是隔离CPU基准，也不证明问题固有计算复杂度。没有改变候选数、beam、滚动长度、方法参数或已完成单元；不重复启动结果目录。

这是离线仿真：真实计算期间`env.time`不推进，5 s决策周期指仿真时钟。服务指标不含真实计算等待产生的交通推进；超过5 s的决策说明当前实现不满足该实时节拍，不能用离线服务结局证明在线部署性能。
