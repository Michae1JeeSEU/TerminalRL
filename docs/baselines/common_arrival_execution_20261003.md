# 共同到达评估环境与空域公平性

本文记录 opt-in `common_arrival_bridge_v1`，入口为
`terminal_marl/scripts/evaluate_common_arrival.py`。这是外部基线的共同执行桥接环境，
不是已经完成的三环主实验，也不改变 CURRENT_STATUS 中训练和 qualification 的状态。
没有启动训练；没有生成或替代 Waltz 权重。

## 1. 三环与自由航向如何公平比较

**统一外部资源与需求，不强行统一内部组织结构。** 共同评估场景应固定外边界、
可用高度范围、禁飞区、入口、着陆点及服务能力、机型动力学、安全间隔和输入请求流。
三环方法在这片空域中组织航线；自由航向方法可以使用整个允许区域。不能在后台要求
自由航向控制器先切环、沿环排队或遵守三环专有的 WAIT/RELEASE 动作。

几何上，固定间隔下环线的可排列位置随总周长增长，而平面可排列位置随可用面积增长；
但这仅是粗略的静态容纳关系。自由飞行的交叉冲突、转弯半径、进近汇聚与着陆点服务，
都会影响实际可持续流量。环形组织牺牲部分路径自由度，可能换来更容易协调的运行秩序。
因此“空中架数更多”不能直接等同于“降落吞吐更高”。也不能据此预先判定三环必败。

建议正式论文分开回答以下问题：

| 实验 | 共同条件 | 允许变化 | 能支持的结论 |
|---|---|---|---|
| 同预算系统对比 | 同一三维空域、入口流、机型、安全与服务资源 | 自由航路、固定三环、动态三环各自的组织方式 | 整套交通组织系统的代价与收益 |
| 动态构型消融 | 同样三环、低层决策器、轨迹与安全模块、需求 | 冻结构型 / 动态调节 | 动态构型的增量作用 |
| 协同策略消融 | 相同几何构型、资源与执行模块 | 规则 / 学习型降落意图 | 决策策略的增量作用 |
| 二维共同能力对比 | 相同单高度可用区域与共同末端降落段 | 自由飞行 / 平面结构化组织 | 二维交通管理的差异；不能代表三维主方案 |

**单高度不等于单环。** 二维公共区域仍是一整片圆盘，环形控制器可以在同一平面选用
多个同心环。只保留一个强制环会同时限制两类方法，不能用来解决公平性问题。

**高度是资源，必须对齐。** 原版 Waltz / Yang 的二维策略若仅能在一个高度运行，
不能直接与可使用三个高度层的主方案对比后声称“算法更优”。可先报告上述二维共同能力
结果；三维系统表中若使用分层复制的二维控制器，必须给所有方法相同的层、入口层分配器、
换层规则及换层代价，并标为新增适配方法。若自由飞行方法没有换层能力，该差异必须作为
能力边界报告，不能用面积或体积归一化把它掩盖。本轮尚未实现三维分层适配。

**不强行匹配空中架数。** 使用完全相同、事先生成的外部请求时间与入口。共同入场保护
基于实际位置放行，未能放行者保留在外部队列。从请求发生开始计时，报告外部排队、内部
逗留、未完成请求数及其年龄。限制入场不能把等待代价从结果中删除。

## 2. 如何选定正式场景

从研究需求及平台范围确定外边界和高度，而不是根据某个方法的成绩挑尺寸。着陆点数量、
服务分布和物理限制以论文所声称的应用为准；同一场景内对所有方法冻结。环半径与高度
是环形方案的设计变量，其可调范围不得越过公共预算。

用独立开发集确定一套固定三环参数，给予自由飞行规划预算、调参时间等同等开发机会。
固定三环应是调过参的合理方案，不能刻意采用劣质尺寸。正式测试前冻结参数、请求流及
随机种子。Waltz 零样本迁移和未来重新训练的同场景策略分开命名；本轮不训练。

主评估采用低负荷、接近瓶颈、高负荷三个需求水平，再加入一次突发和一次方向偏移即可。
负荷按相同服务资源与共同参考处理能力设定，不为每种方法分别调整到达率。以固定观察窗
统计服务完成吞吐、积压增长与失败；必要时增加独立清空阶段，分别报告窗口内吞吐与
清空时间。有限四机/六机任务的完成率不是可持续容量估计。

若论文主张空域利用改善，再做同样的两至三个公共尺寸预算，绘制吞吐—延误—预算关系；
不必先把三环和自由飞行的最大容纳架数调成相同。动态方案始终受同一最大边界约束，
不能获得未记账的额外空域。

## 3. 本轮实际实现的桥接场景

| 项目 | bridge v1 |
|---|---|
| 空域 | 半径 800 m 的圆形区域；到达巡航高度 100 m；没有强制环 |
| 导航参考 | 规则与 MCTS 等待目标可取半径 440 m 的软参考点；环境不要求沿该半径飞行 |
| 入口 | 北、东、南、西四个固定入口，固定请求流；入场缓冲含安全间隔及制动距离 |
| 末端资源 | 中心单着陆点，200 m 进近捕获区；仅获授权者进入；捕获到地面服务结束占用资源 |
| 服务 | 同质请求，落地后 60 s 地面服务；服务完成才计 completed |
| 运动 | 巡航目标 13 m/s；航向意图上限 5°/s；1 s 决策，0.2 s 执行采样 |
| 安全 | 公共 80 m 期望间隔、40 m NMAC、10 m 碰撞阈值；沿用项目研究机型动力学 |
| 轨迹 | V3 五次多项式，SafetyFilter 检查、绑定轨迹哈希，RuntimeSeparationMonitor 检查执行 |
| 能量 | phase_motion_v2 归一化代理；容量 1e6，刻意排除本轮能量瓶颈，不作为续航结论 |
| 信息 | 控制器使用已准入飞机状态；MILP 不读取未来请求；无位置噪声 |
| 规划预算 | MCTS 100 次搜索、深度 3；MILP 2 s 求解上限；5 s 规划迟到阈值 |

公共执行器将航向意图转换为受限轨迹。请求轨迹不安全时，依次尝试公共避让、制动、
已认证轨迹剩余段；均不能通过则 fail_closed，不继续推进。制动可进入低速/悬停，属于
共同执行器的适配能力，与原版自由飞行运动模型不同。每步记录干预与执行轨迹哈希。
这使对比对象成为“方法 + 同一执行器”，不能把经过安全过滤的分数冒充原论文分数。

5 s 阈值表示迟到规划结果不用于本步航向，回退到公共规则；不是强制杀死计算线程的实时
保证。仿真采用逻辑时钟，计算耗时不直接增加飞行延误，单独报告 latency 与迟到次数。
MILP 超时无可行解或残差超限时退回 FCFS，必须同时看 solver_accepted。

该桥接采用单着陆点、同质服务、充足能量，是接口与执行验证的最小共同任务。
主项目当前三环、多个 LZ、异质服务与能量压力尚未全部接入此桥接。后续正式主表要按
第 1–2 节扩展公共能力；不能直接拼接本桥接分数与 TerminalParallelEnv 的分数。

## 4. 各基线保留与改动

| 名称 | 实际调用 | 明确的适配 |
|---|---|---|
| `fcfs_rule` | 项目新增 FCFS + 有界航向引导 | 公共规则参照，不冒充某篇论文 |
| `yang_mcts_adapted` | 原作者 MultiAircraftState / MultiAircraftNode / MCTS | SI 速度/间隔/边界参数；公共 1 s 决策；FCFS 资源授权与软等待目标；V3 执行 |
| `saxena_milp_adapted` | 已有 SciPy/HiGHS 源公式移植 ScheduleModel | arrival-only 因果滚动求解；入场时间等式改下界允许等待；增加物理最早到达及着陆/服务占用约束；共享导航执行 |
| `waltz_actor_adapted` | 原作者观测构造、LSTMRecActor、strict 权重加载 | EN/NE 坐标及航向转换；2 步历史；原 1000 m 观测归一化；共同资源与轨迹执行 |

Yang 的源搜索树仍使用原 10 帧预测和原 reward；预测模型不等于 V3 执行模型，干预率
是必要结果。修复的字符串/NumPy action 比较只在内存加载时生效，原始源码快照不改动。
MCTS 随机数状态与请求生成器隔离，不使不同方法看到不同流量。

Saxena 的原节点拓扑与目标函数作为排程代理保留，原图边长不代表公共执行轨迹。
R2 时隙映射为最早捕获时间和目标接地时间，实际接地偏差记入 capture 事件；无可行解
不伪造最优排程。Python 移植尚无 MATLAB 同输入数值等价结论。桥接同质小规模场景中
它可能与 FCFS 选到相同顺序，这既不是算法没有作用，也不是 MILP 优势的证据。

Waltz 缺作者权重时输出 `skipped_missing_checkpoint`、`performance_valid=false`。
适配代码的存在不表示 trained Policy IV 已复现；拿到权重后仍需验证本桥接上的迁移表现。
若将来重训，须另行确定训练/测试分离和预算，命名为同场景重新训练基线。

## 5. 运行与结果

三个配置位于 `terminal_marl/configs/common_arrival/`，均可使用以下命令；Python 环境需
NumPy、SciPy（HiGHS）；MCTS 与规则本身不需要 Gym、ROS2。Waltz 推理额外依赖其 native
wrapper 的依赖和 OpenAP 资源，详见 `baselines/waltz2024/README.md`。

本轮已验证 CPython 3.12.14、NumPy 2.3.5、SciPy 1.16.2（Windows x64），版本清单位于
`terminal_marl/configs/common_arrival/requirements.txt`。可在独立 Python 3.12 虚拟环境中
执行 `python -m pip install -r terminal_marl/configs/common_arrival/requirements.txt` 后运行
同一入口。每次输出都会记录实际版本；不要把不同求解器版本的耗时混为同一硬件/软件实验。

```powershell
# 本机本轮运行环境：bundled Python + 项目临时目录中的 SciPy
$env:PYTHONPATH = '.tmp/common_arrival_deps'
& 'C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m terminal_marl.scripts.evaluate_common_arrival --config terminal_marl/configs/common_arrival/balanced.json --seeds 20261004 --output "$env:TEMP/common_arrival_balanced_new"
```

输出目录必须新建且在源码仓库之外，避免覆盖旧结果。服务器通过 Syncthing 获得代码后，
使用具备 NumPy/SciPy 的环境执行同一模块，输出限定 `$HOME/training_outputs/terminal/…`；
不上传代码、不修改共享环境、不把产物写入服务器项目目录。本轮验证位置以文末记录为准。

每个 method/seed 输出：`metrics.json`、`metadata.json`、`requests.json`、`aircraft.csv`、
`actions.csv`、`trajectories.csv`、`ticks.csv`、`events.json`、`planner_calls.json`、
`solver_records.json`。根目录 `summary.json/csv` 可直接聚合；请求 SHA 必须一致。

主要指标包括服务完成数/率、以固定计划窗口为分母的吞吐、有限任务清空速率、请求至服务
完成时间、外部等待、未完成请求年龄、队列与空中飞机数的时间积分、路径长度、归一化能耗、
最小实际/扫掠间隔、冲突/NMAC/碰撞、资源占用、公共安全干预率、规划耗时及 MILP 接受数。
请求至完成是总逗留时间，不直接称作扣除了无拥堵飞行时间的“净延误”。
没有飞机对时最小间隔写 null，不写 Infinity。失败/skip 不作为有效性能样本；
truncated 保留未完成请求，不能只比较已完成者的平均时间。

清空用时 492–496 s，MCTS 523–527 s。这些是联调观察，不是论文排名或容量结论。
输出：`C:/Users/user/AppData/Local/Temp/common_arrival_matrix_upz8j1xi`。
最终配置运行原始目录：`C:/Users/user/AppData/Local/Temp/common_arrival_final_qt3_gvd6`。
已将 12 组完整产物归档到
`D:/7_codespace/training_outputs/terminal/common_arrival_bridge_20261003/`（120 个文件）。

最终配置回归：seed 20261004，balanced 六架、bursty 四架、direction_shift 六架，
三方法共九个有效运行、48 架次，全部完成服务；operational-buffer/hard/NMAC/collision
的 entry 与 exposure 计数均为 0；规划迟到回退均为 0。Saxena 在三个场景中分别接受
6/6、4/4、6/6 次求解。三个 Waltz 条目均为缺权重 skip，不包含在 48 架次中。
