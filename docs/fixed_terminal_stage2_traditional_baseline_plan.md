# 固定多环终端区联合调度研究重构计划：阶段2

## 阶段1审查结论

阶段1已经完成的问题合同冻结：

-   固定三环终端区；
-   固定安全规则；
-   固定容量；
-   固定能源模型；
-   固定正常/应急/失败定义；
-   固定评价指标。

阶段1验证证明：

1.  仿真模型内部一致；
2.  安全检查、容量约束、能源检查链路可运行；
3.  高密度初态和随机SOC场景可以生成；
4.  低SOC、高负载会产生应急和能源压力。

但阶段1没有回答：

> 在该固定问题定义下，什么样的调度方法能够实现更高效、更可靠的降落？

因此阶段2目标不是设计RL，而是建立传统方法性能边界。

# 阶段2总体步骤

## Step 2.1 建立基础排序规则基线

目标：

建立简单但合理的参考。

实现：

### FCFS

按照请求进入时间排序。

用途：

最低复杂度参考。

------------------------------------------------------------------------

### SOC priority

按照当前SOC排序。

用途：

复现传统低电量优先思想。

------------------------------------------------------------------------

### Energy slack priority

按照能源余量排序。

核心：

不是最低SOC优先，而是：

当前SOC - 完成最低可行任务所需SOC。

------------------------------------------------------------------------

### Deadline/slack priority

定义：

最后可正常完成窗口 - 当前时间。

用于表示能源和资源共同形成的紧迫性。

------------------------------------------------------------------------

输出：

基础规则性能。

------------------------------------------------------------------------

# Step 2.2 建立联合可行窗口调度

目标：

从单机priority进入真正联合调度。

核心思想：

每架飞机不是一个排序对象，而是一组可执行候选窗口。

候选包括：

-   当前环等待圈数；
-   跨环时间；
-   最后进近窗口；
-   pad时间。

调度目标：

选择一组互相兼容的窗口。

约束：

-   安全；
-   容量；
-   能源；
-   pad。

------------------------------------------------------------------------

# Step 2.3 建立滚动优化基线

目标：

提供强传统参考。

候选：

## Rolling horizon search

每个事件：

1.  获取当前状态；
2.  生成候选；
3.  搜索未来窗口；
4.  执行第一步。

------------------------------------------------------------------------

## CP-SAT/MILP小规模oracle

用途：

不是部署。

用于回答：

当前启发式距离较优解多少。

------------------------------------------------------------------------

# Step 2.4 明确调度问题的真正难点

重点分析：

## 难点1：能源约束

问题：

SOC是否决定排序？

验证：

比较：

-   SOC；
-   energy slack；
-   deadline slack。

------------------------------------------------------------------------

## 难点2：空间容量

问题：

是否主要由环容量导致？

分析：

-   不同占用率；
-   不同请求强度。

------------------------------------------------------------------------

## 难点3：未来影响

问题：

当前放行是否影响后续？

分析：

比较：

-   greedy；
-   lookahead；
-   rolling optimization。

------------------------------------------------------------------------

## 难点4：计算复杂度

记录：

-   候选数量；
-   搜索时间；
-   飞机数量增长。

------------------------------------------------------------------------
