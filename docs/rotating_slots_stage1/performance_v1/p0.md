# P0 来源与语义基础

状态：`IMPLEMENTING` / `NOT_QUALIFIED` / `HUMAN_PENDING`。

本轮只实现 FT-RS-S1-PERF-1.0 的来源、规则预检及隔离查询基础。没有性能结果、完整来流资格、70 项目录全覆盖或人工回放签收。A07 观测 shim 与 A08 发布分类器不在本文件的完成范围。

## 固定参照

R0 为 `1c5afd37c891a0ed4776f64367fc7264db3c1c54`，policy 为 `upstream_capacity_only_pad_arrival_v1_20261018`。本地 ignored 目录 `artifacts/rotating_slots/performance_reference_r0/` 含 24 个 Git 原始文件及 `.reference_manifest.json`；包含 rotating_slots 包、两级 package 初始化文件、`new10.16/` 与 Oct18 修订。路径到 SHA256 映射的摘要为 `cd76b4c14b0a48d6d2a71ec7c63ce77010e6ea019b545807635b926eb2984891`。

导出用本地 `git -c core.autocrlf=false archive`，逐文件核对 Git blob ID 后写入新目录。关闭 autocrlf 是为了保留 Git 对象原始 bytes；默认 Windows archive 会转换部分换行。API 不覆盖既有导出；每次查询前后核验全部文件及固定摘要。这里的不可变性指固定内容和拒绝篡改，不声称提供操作系统写保护。未创建历史 H0 计时参照，未向服务器手动传输文件。

`run_reference()` 创建新的 `python -I -B` 子进程，移除 PYTHONPATH/PYTHONHOME，先插入 R0 根目录，检查所有 `terminal_marl` 模块实际路径属于已验证导出。父进程已导入的优化模块与全局 cache 不进入该子进程。子进程返回实际导入路径、文件 hash、PID、配置身份与查询结果。它是研究 oracle 的进程隔离边界，不是执行不可信代码的安全沙箱。

## 对接 API

以下函数位于 `terminal_marl.core.rotating_slots.performance.provenance`：

```python
export_reference(repo_root, destination) -> dict
verify_reference(repo_root, reference_root) -> dict
run_reference(reference_root, modules=(...world, ...driver),
              code=None, timeout=60, python=None) -> dict
implementation_fingerprint(root, extra_paths=(), modules=None) -> dict
verify_deployment(root, expected_manifest, supplied_commit=None) -> dict
semantic_fingerprint(root, *, policy_id=None, assertions=None,
                     candidate_policy=None, numerical_policy=None) -> dict
require_same_semantics(reference, current) -> dict
```

`run_reference` 的 `code` 在子进程设置可 JSON 序列化的 `query_result`；stdout 单独捕获。默认 timeout 是有界查询的 60 秒，非完整 episode 预算。`implementation_fingerprint` 的 `extra_paths` 应传入 CLI、测试入口与包外本项目 wrapper；默认递归覆盖 `terminal_marl/`、`scripts/` 的 Python/native 源码与编译产物、冻结配置、合同包及修订，并附加已经导入的项目文件。venv、site-packages 与 Python cache 不计作项目实现。启动后新增导入需要在结束时再次采集；依赖版本/依赖库 provenance 由运行入口另行记录。

部署清单应由本地 launcher 生成：在 `implementation_fingerprint` 返回值增加真实 `implementation_commit`，把整个清单作为服务器核验的可信预期输入。`verify_deployment` 不调用 Git，比较完整文件映射、摘要及显式/环境 commit 标签；仅有 `TERMINAL_CODE_COMMIT` 会拒绝。它验证清单与部署内容的一致性，不认证来自不可信来源的清单。工作树存在修改时不能把该映射声称为原提交的精确内容；提交标签与实际文件摘要须分别记录。

语义结果提供 `schema`、`policy_id`、`config_hash`、`profile_hash`、`vehicle_profile_hash`、`energy_profile_hash`、`physical_config_bytes_sha256`、`effective_rules_hash`、`candidate_policy_hash`、`numerical_policy_hash` 和 `semantic_sha256`。规则哈希覆盖实际 policy 标识、Oct18 修订文本、准入及 pad 保护函数；候选哈希覆盖实际生成、reference、driver 顺序与 phase bins。数值投影读取实际 AST 的根迭代、标量/向量根分支残差 `1e-12`、积分精度/深度、peak/连续验证预算、端点与 C2/源目标/capture/接地 metadata 容差、world 默认周期及 SOC/peak 阈值等命名表达式，未知表达式会拒绝，不用整个实现 hash 冒充语义 hash。

候选/规则函数 AST 是 P0 的保守冻结方式。后续若仅重写这些函数的等价实现，必须先由主对话复核等价证据并明确调整投影；不能直接更新 expected 让测试自洽通过。增加独立 helper 不改变语义 hash。`require_same_semantics` 允许配置 LF/CRLF 原始 bytes 不同，但配置完整解析摘要必须相同；原始 bytes 哈希始终各自保留。修订文本只正规化换行，未删除内容。

合同入口为 `performance.contract.preflight(package_dir, source_root, reference_semantics=None)`。它固定核验主合同/YAML/catalog 的交付 bytes，核对合同/策略/commit、70 ID 与 Markdown 映射、矩阵、物理断言、实际源码语义投影。任何不一致统一抛出 `ContractInconsistent`，code 为 `CONTRACT_INCONSISTENT`。它不修改规范文件或历史结果，不授予性能资格。

原始 8 文件规范包保持 bytes 不变。`.gitattributes` 为该目录指定 `text eol=lf`，避免后续 Windows checkout 的自动换行转换改变规范输入 hash；已有 LFS 规则保留。

后续 R0+OBS runner 需要分别记录 R0 内核清单与外部观测/并行 helper 清单。当前 `run_reference` 只支持纯 R0 项目导入；不可通过混入优化 checkout 的 `terminal_marl` 核心模块来加载 OBS。独立 helper 的双根路径、清单和 shim 零副作用验证由后续运行入口实现，不由本基础 API 默认放行。
