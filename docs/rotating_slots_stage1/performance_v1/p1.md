# P1 checkpoint and observation foundation

Scope: FT-RS-S1-PERF-1.0 sections 7–8. These helpers provide a bounded runner
foundation. They do not qualify full traffic, the six performance windows,
instrumentation overhead, process-tree accounting, or visual acceptance.

## Checkpoint API

`performance.checkpoint.CheckpointIdentity` requires the policy, semantic config,
profile, physical bytes, effective rules, candidate policy, numerical policy and
implementation hashes. `capture_checkpoint(world, identity=..., cursor=...,
driver=...)` returns a tagged plain payload. `write_checkpoint(path, payload)`
writes a hash envelope using a temporary file, flush, fsync and atomic replace.
`load_checkpoint(path, expected_identity=...)` checks the complete envelope and
identity. `restore_checkpoint(payload, expected_identity=..., cache_mode='cold',
world_class=...)` validates and constructs a fresh world without calling its
constructor, `_record`, `_settle`, emergency monitoring, or physical propagation.

`AdvanceCursor(original_target, phase, outer_phase, shim_source_sha256)` preserves
the original advance target and the runner's outer phase. The phases are
`loop_start` (the next original loop iteration remains to execute) and `returned`
(that invocation has completed). `ObservedAdvance.resume(restored)` handles both:
returned checkpoints produce a snapshot and never call advance again.

The explicit world field inventory covers every R0 instance field. Runtime sink,
callback and scheduler port objects are excluded and rebound explicitly. Unknown
fields, callback implementations, tags and types are errors. Supported callback
state is `DeterministicDriver.calls`, including aliasing when the default and
effective driver are the same instance. Full events and rejections are retained;
the source-clear history is never dropped. All authoritative archived trajectory
payloads, hashes, profile/config identities and active/soft archive bindings are
validated before any recovery output is created.

Floats use `float.hex()` tags, including signed zero and typed positive/negative
infinity. Dictionaries are ordered pairs and preserve integer/tuple keys.
Whitelisted dataclasses retain their explicit fields; constructors must reproduce
their serialized representation exactly. Config/Section, calendars, reservations,
aircraft/emergency state, manifest/requests, plans/segments and energy results use
classes from the supplied world's core package. The code never imports a second
core namespace into an isolated R0 process.

Derived qE, energy and canonical-template memoization are a separate payload.
Cold restore clears all three tables; warm restore preserves their types and
insertion order. The canonical representative policy remains R0's fixed 24-bin
rule. No candidate policy or numeric computation is changed by these helpers.

`register_equivalence_migration(id, source_identity, target_identity)` accepts
only an explicit exact implementation pair with identical semantic identities.
The runner must pass that registered ID to restore. Registration itself does not
certify equivalence; it is a caller action for an already qualified pair. There
is no arbitrary trust flag and no automatic cross-implementation acceptance.

`CheckpointStore(directory).save(payload, pinned=False, corpus=False,
milestone=None)` atomically updates its complete-checkpoint index. It retains the
latest two checkpoints, the latest eight corpus cuts, and every explicit pin or
milestone. It is a single-writer store. Unindexed partial temporary files are not
accepted as checkpoints. POSIX directory fsync also persists the rename; Windows
uses file fsync plus `os.replace`, since directory descriptors are unavailable.

## Stream recovery

The existing `BufferedStateJSONLSink` is supported without changing replay.py.
Capture flushes/fsyncs the latest frame, saves the immutable prefix offset/hash,
pending latest-frame bytes/hash/time and committed-frame count. Restore verifies
the prefix hash, complete-line boundary, strict time order/count and the pending
frame against the world's retained frame. Same-time replacement may change the
source's uncommitted tail after a checkpoint; the checkpoint's saved pending
frame remains the authoritative recovery frame.

Stream restoration requires `new_attempt_dir` that does not exist and lies
outside the original attempt. The verified prefix and saved pending frame are
copied there. Partial or complete post-checkpoint tails are discarded only in
that new copy. Original files are opened for reading only. The resumed sink keeps
the original latest-frame replacement offset, avoiding duplicate same-time rows.

## Observation and measurements

`make_observed_advance(RotatingSlotWorld)` generates a function from the supplied
class's exact `advance` source. Original algorithm lines and globals are retained.
The only inserted observation calls are after the existing final loop `_record`
and before the existing return. Source shape changes fail closed. The helper
returns original/generated source hashes and a unified patch; the runner must
persist these as the R0+OBS instrumentation record. External helper code can be
loaded under the isolated core package's `performance` namespace, keeping all
world, plan and energy classes from that isolated process.

`CutRequests(on_capture)` requests every 30 simulated seconds or 300 wall seconds,
plus optional `requested_sim` milestones. Non-grid requests wait for an existing
cut and record actual/requested time and deferral. The hook never calls advance,
settle or emergency code. `SuspendAtCut` is a nonphysical suspension signal for
bounded capture. The runner persists its own observer cadence/milestone cursor;
these helpers do not imply that a full CLI or episode supervisor exists.

`Measurements('benchmark'|'profile')` labels wall time with `perf_counter` and
parent process CPU with `process_time`. Benchmark mode refuses cProfile. Profile
mode requires an explicit bounded `profile_batch(path)` and uses a process-CPU
timer. Nested spans are marked nonadditive. R0's `world.cpu` wall counters are not
summed as CPU. Process-tree CPU is explicitly unavailable until a supervisor
supplies child accounting; parent-only measurement is not full CPU qualification.

`PassiveHeartbeat` uses an independent observer thread. The runner publishes last
complete simulation time and active query context; no live world is read or
advanced by that thread. It writes a 30-second wall heartbeat, reports
`SLOW_OPERATION` after 300 seconds without a completed step and dumps parent
thread stacks after 1800 seconds. Child-stack coverage is explicitly unavailable.
`check_health()` and `close()` expose observer I/O failures to the runner.

## Bounded evidence

The focused suite covers full mixed-state serialization; integer keys, order,
tuples, infinity and signed zero; known driver binding; same-time request/service
events and source-clear history; non-grid cut deferral; interrupted continuation;
prefix/pending corruption and copied-tail recovery; atomic rename fault injection
and retention; identity/schema/hash/migration rejection; archive-plan corruption;
cold/warm exact energy queries; replay-versus-checkpoint rejection; measurement
mode separation; and passive heartbeat state/error reporting.

The real A07 case seeds one inner-ring holding aircraft at SOC 0.9 with default
emergency handling, callback=False and no replacements of core methods. It
compares an ordinary 0→0.4-second invocation with observation enabled, then with
0.2-second suspension/cold restore into that same original 0.4-second target.
Frames, aircraft state, qE/SOC hex values, authoritative trajectory hashes,
events, rejections and decision times agree. Only measured wall counters, cache
counts and reference-work counts are excluded from physical comparisons.
