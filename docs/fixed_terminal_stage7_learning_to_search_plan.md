# 固定多环终端区联合到达调度研究重构计划：阶段7

## 阶段6审查结论

阶段6完成了学习排序器作为搜索加速器的验证。

核心结论：

1.  学习排序模型能够预测部分候选优劣；
2.  但排序收益没有转化为完整调度计算收益；
3.  rollout数量减少并没有显著降低总决策时间；
4.  与强beam搜索相比，当前学习排序没有额外优势。

因此：

## 停止扩展学习排序方案

不再继续：

-   更复杂ranking模型；
-   更大网络；
-   GNN排序器；
-   Transformer排序器。

但是不完全放弃学习。

原因：

阶段6验证失败的是：

> 学习作为候选排序器。

而不是：

> 学习参与搜索过程。

------------------------------------------------------------------------

# 阶段7目标

## Learning to Search：学习驱动的联合调度搜索

核心问题：

> 在能源约束、多环容量和安全约束共同作用的联合调度问题中，学习方法是否能够减少搜索资源消耗，同时保持传统优化方法的调度质量？

------------------------------------------------------------------------

# 阶段7核心原则

## 学习不负责最终决策

保持：

-   安全验证；
-   能源检查；
-   容量检查；
-   轨迹可执行性。

全部由确定性模块完成。

------------------------------------------------------------------------

## 学习负责搜索过程

学习可以决定：

-   哪些节点值得展开；
-   哪些分支可以提前剪枝；
-   当前状态需要多少搜索预算；
-   beam宽度如何调整。

------------------------------------------------------------------------

# 阶段7总体步骤

------------------------------------------------------------------------

# Step 7.1 分析传统搜索瓶颈

目标：

确定搜索浪费在哪里。

不是马上训练模型。

首先分析：

## Beam搜索过程

记录：

每个搜索节点：

-   depth；
-   candidate数量；
-   是否最终进入最优方案；
-   rollout结果；
-   certificate结果。

建立：

搜索树数据库。

------------------------------------------------------------------------

## 分析指标

统计：

### 无效搜索比例

即：

被验证但最终没有贡献的节点比例。

### 不同深度价值

分析：

哪些深度最影响最终方案。

### 分支价值差异

分析：

是否存在：

少数关键分支决定最终结果。

------------------------------------------------------------------------

# Step 7.2 建立学习剪枝模型

目标：

学习：

> 哪些搜索节点值得继续展开。

------------------------------------------------------------------------

输入：

partial plan状态：

包括：

-   已选择动作；
-   剩余飞机；
-   剩余资源；
-   SOC状态；
-   当前目标值；
-   剩余搜索预算。

输出：

expand probability。

------------------------------------------------------------------------

注意：

模型不是判断最终方案。

只判断：

是否值得消耗计算资源。

------------------------------------------------------------------------

# Step 7.3 建立动态beam搜索

目标：

替代固定beam width。

当前：

固定：

B=3/5/8。

改为：

\[ B_t=f(s_t) \]

根据状态动态调整。

例如：

简单状态：

小beam。

复杂状态：

扩大搜索。

------------------------------------------------------------------------

# Step 7.4 建立学习辅助搜索框架

最终结构：

    状态
     ↓
    候选生成
     ↓
    学习搜索策略
     ↓
    选择expand/prune
     ↓
    确定性rollout
     ↓
    安全/能源验证
     ↓
    提交方案

fallback：

如果学习剪枝导致：

-   无可行方案；
-   质量下降；

自动恢复：

beam/full search。

------------------------------------------------------------------------

# Step 7.5 建立严格比较实验

比较对象：

## 传统方法

-   beam3；
-   beam5；
-   beam8；
-   adaptive beam；
-   full reference。

## 学习方法

-   learned pruning；
-   learned beam width；
-   hybrid。

------------------------------------------------------------------------

评价：

## 调度质量

包括：

-   正常完成数量；
-   应急数量；
-   能源失败；
-   延迟。

------------------------------------------------------------------------

## 搜索效率

包括：

-   rollout数量；
-   expanded nodes；
-   candidate验证次数；
-   wall-clock time。

------------------------------------------------------------------------

## 鲁棒性

测试：

-   不同SOC；
-   不同负载；
-   不同初始占用。

------------------------------------------------------------------------

# 阶段7数据需求

优先使用：

已有：

-   beam搜索记录；
-   rolling结果；
-   full reference结果。

构造：

搜索轨迹数据。

不需要重新设计teacher。

------------------------------------------------------------------------

# 阶段7禁止事项

禁止：

-   PPO；
-   offline RL；
-   多智能体；
-   端到端动作控制；
-   学习安全规则。

原因：

当前研究问题仍然是搜索效率，而不是控制策略。

------------------------------------------------------------------------

# 阶段7结束后的决策

## 情况A

学习搜索没有减少计算：

停止学习路线。

最终方法：

传统联合优化调度。

------------------------------------------------------------------------

## 情况B

学习搜索减少计算，质量保持：

形成：

Learning-assisted optimization。

这是最理想结果。

------------------------------------------------------------------------

## 情况C

学习搜索发现传统搜索遗漏高价值方案：

进一步研究：

学习长期价值。

------------------------------------------------------------------------

# 当前研究边界

继续保持：

不研究：

-   动态空域；
-   自由飞行；
-   有限感知；
-   分布式多智能体通信。

固定多环终端区联合调度仍然是当前唯一研究对象。
