# 2026-05-30

## 完成事项

- 诊断随机 N=10-40 多规模训练效果退化问题：
  - 固定 N 的 `Phase3bWrapper` 未在 reset 时写回 `config.num_uavs`，导致 eval callback 可能并未按目标 N 选 best model。
  - 多环境 factory 复用同一 `EnvConfig` 对象，存在 wrapper 动态修改 `num_uavs` 后互相污染的风险。
  - 大规模训练下 near-miss / safety pair penalty 随 N 放大，而单架着陆奖励被 `num_uavs` 稀释，PPO 容易学成拖延策略并触发 timeout。
  - DESCEND 放行阻塞包含正常排队/计时/容量过滤，不应默认作为失败惩罚。
- 修改训练代码：
  - `Phase3bWrapper.reset()` 固定写入 `n_uavs`。
  - `make_env_phase3b()` 为每个 env 深拷贝 config。
  - `MultiScalePhase3bWrapper` 改为课程式随机 N：先采 10-20，再采 10-30，最后采 10-40。
- 修改 reward 尺度：
  - 着陆奖励改为跨 N 稳定的 per-landing spike。
  - 近距预警惩罚按受控 UAV 数归一化。
  - `safety_margin_penalty_scale` 从 1.5 降到 0.75。
  - `penalty_descent_block` 默认改为 0.0，仅保留观测信号。
- 修复 `max_steps` 的 Gymnasium 语义：时间上限现在返回 `truncated=True`，不再误报为 `terminated=True`。
- 修复 `_diagnose_phase3b.py` 中的 landing rate / timeout 统计口径：landing rate 改为 `landed / n_uavs`。
- 补充测试覆盖固定 N reset 和课程采样范围。
- 补充测试覆盖 max_steps truncation。
- 同步更新 requirements / technical_spec / design_spec / execution_plan。
