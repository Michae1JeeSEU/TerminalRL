# 开发日志 2026-05-18

## 完成事项

### 1. 碰撞处理机制重构：终止 episode → 移除碰撞 UAV

**问题**：碰撞发生后直接终止整个 episode，导致高密度场景下（N≥20）大量剩余 UAV 被强制丢弃，PPO 无法获得完整的降落学习信号。

**修改**：
- [x] `terminal_area_env.py`：碰撞后标记 UAV `battery=0`（`is_dead=True`），释放 LZ 预留，施加惩罚 `-(500 + 250*N_colliding)`，**不终止 episode**
- [x] `uav.py`：`step()` 增加 `is_dead` 检查，死亡 UAV 不再移动
- [x] `test_env.py`：更新碰撞测试为 `test_collision_kills_uavs` + `test_collision_does_not_terminate_episode`
- [x] 修复 `cfg` → `self.config` 变量引用错误

### 3. 训练配置

- **模型**：PPO, max_n=100, N=10 训练, 500k steps, 4 SubprocVecEnv
- **架构**：PerUAVFeatureExtractor (mean pooling), 75→128→64 encoder, 128→32→8 combiner
- **训练时间**：3999.5s (~67 分钟), 125 FPS
- **Best model**：EvalCallback @10k steps, eval reward +113.75
- **Final model**：eval reward +103.70 @500k steps

## 关键发现

1. **碰撞移除机制是高密度性能提升的主要因素**：之前 N=30 PPO 仅 17%（episode 提前终止后大量 UAV 未降落就被丢弃），改为移除后提升至 79%
2. **PPO 在 N=15/20 超越 Heuristic**：说明 PPO 学到了比贪心启发式更好的协调策略
3. **N≥25 时碰撞仍是瓶颈**：PPO 碰撞 1.9-3.1 次/episode，无法满足实机验证的零碰撞要求
4. **SafetyController 已集成**：Plan B 方式（safety 信号 +4 维输入观测），但高密度下碰撞仍多
