## 1. Stage3的两条问题线，分开实现与评价

### 1.1 已批准主线A：学习辅助候选构造

学习问题：给定当前可见状态、已构造的候选/部分链与剩余预算，**下一项哪种轨迹构造工作值得优先计算？**

可选工作包括飞机、源环槽位、目标槽位或pad、启动偏移、机动时长，以及对一条已验证部分链的下一步扩展。学习不是输出最终着陆命令，不直接分配不可撤销资源。

目标是：在共同质量定义下，减少真实昂贵调用和完整正常规划时间；或者在相同预算内获得更好的已验证方案。两种比较不能混为一谈。

加速空间须按实际工作量解释：`T_new = T_fixed + T_feature + T_inference + T_materialize_new + T_validation_new + T_CP + T_fallback`。改变候选顺序不会自动减少全部最终认证或公共执行成本；本阶段不预先承诺把20秒变成5秒。

### 1.2 预留线B：下游等待/末端价值学习

学习问题：某个已定义预测状态或联合暂定方案，未来还有多少等待与能耗负担？

本版只建立数据、版本和接口，不训练或启用末端价值头，不把学习末端值写入CP。Stage2先完成共同的下游服务估计和目标修正；随后才决定是否训练残差价值模型。候选加速和改目标不可在同一初次对比中同时打开。

### 1.3 本阶段不开展

本轮不启动在线PPO/多智能体RL、全场景世界模型、神经安全认证、神经动力学、端到端速度或轨迹控制、CP branching策略、动态空域、异构机型及硬件迁移。这是已经批准的首轮边界，不表示这些方向理论上不可行；扩展范围必须另开后续版本。

## 2. 不变边界

物理、数值后端、资源规则、失败后隔离继续的定义、准入和应急均由当前Stage1/Stage2有效版本统一提供。Stage3不重设80m安全间隔、运动包线、正常25%接地储备、功率预算或服务时间。

正常飞行仍按相邻环转移；已开始机动不改目标；未来预测不自动成为执行命令。学习分数不能使UNKNOWN变为SAFE，也不能覆盖真实资源冲突或已承诺依赖。

**模型不承担最终安全保证。**安全仍取决于共同验证器及其模型假设；筛掉有价值分支仍可能增加等待、应急或能源失败，因此“最终动作通过安全验证”不等于“调度质量不会下降”。

当前有效应急版本与政策覆盖层以运行指纹为准，不能仅凭旧YAML里的字段判定实际行为。

## 3. 并行开发方式与版本契约

### 3.1 Stage2拥有的事实源

Stage2改变评分后，Stage3学习的“哪个方案好”标签必须重新计算或重新收集，不能无提示继续使用旧标签。基础物理尝试记录可在兼容性检查后复用，但它们不自动成为新目标下的偏好标签。

## 5. 学习对象：WorkDescriptor，而不是已完成的PredictionColumn

### 5.1 描述结构

使用以下不可变记录语义，名称可按现有代码风格调整：

```python
@dataclass(frozen=True)
class WorkDescriptor:
    descriptor_id: str
    snapshot_id: str
    source_node_id: str
    aircraft_id: str              # 关联标识，不直接作为模型数值特征
    source_ring: str
    source_slot: int
    target_kind: str              # next_ring_slot / normal_pad
    target_id: int
    start_offset_s: float
    duration_s: float
    parent_prefix_id: str | None  # 已实例化父链，不是尚未验证的假想状态
    construction_stage: str       # progress / reference / alternative
    proposal_origin: str         # current / delayed / resource_aligned / reuse
    inherited_order: int
```

`materialize(snapshot, descriptor)`返回真实轨迹/验证结果/计算成本，并记录生成出的候选或后继描述ID。候选提议与真实飞行动作必须采用不同类型。

### 5.2 必须满足

描述符只能使用本版本传统生成器允许的目标和时刻族。第一版不让模型自由输出连续时间或任意轨迹系数，以免同时扩大动作空间。

多步子描述只有父链已经确定、对应源状态和剩余能量已计算后才进入就绪池。若有“探索某分支”的粗粒度工作，应单独建类型和成本，不混成已知完整轨迹。

候选池按需、分批枚举，不先穷举所有目标×时长×偏移×深度。首版Advisor排序一个有界就绪批次，传统确定性机制继续供给后续批次；模型不能凭空删除批次外对象。就绪批次上限为64；每批最多执行8项工作或在候选/资源/覆盖发生实质变化后刷新评分。该上限是计算工作批次，不是飞机、可行动作或空域容量限制。

### 5.3 核心接口

```text
ProposalSource.peek_ready(snapshot, catalog_state, budget) -> descriptors
FeatureEncoder.encode(snapshot, descriptors, observed_search_state) -> features
ProposalAdvisor.rank(features, budget) -> ordered_ids, model_metadata
Materializer.evaluate(descriptor) -> factual_result, descendants
TraceObserver.record_before/after(...) -> bounded log
```

`rank`返回的必须是输入就绪描述ID的合法排列或显式受限选择，不接受新造ID。低分仅影响计算优先级，不作为物理不可行判决。

## 6. 输入表征：保留飞机、相位和资源的对应关系

### 6.1 首版特征

| 层次 | 允许特征 |
|---|---|
| 本机 | 环/槽位几何、sin/cos相位、SOC、峰值余量、服务类别、到达/盘旋时长、当前状态与承诺结束时间 |
| 候选工作 | 目标相对相位、启动偏移、时长、预计汇入时间、父链深度、目标资源、即时/延后/复用来源 |
| 资源 | 六pad现有与未来保护区间、服务结束时间、下一环槽位释放、当前已承诺机动 |
| 多机竞争 | 候选条件下相关飞机的相位、SOC、服务需求、进入下游的预计时间；空间邻近与资源竞争关系分别表达 |
| 搜索上下文 | 已尝试工作、已知失败原因、当前各机/各目标覆盖、完整链缺口、已用/剩余预算、有效已有缓存标记 |
| 下游估计 | Stage2现有轻量排队估计、各环等待功率、候选到达时段的工作量；没有实现时置missing mask，不编造值 |

所有时间用相对快照时刻，角度用周期表示，能量/SOC/功率使用明确单位和归一化。标准化只在训练集拟合。

### 6.2 禁止泄漏与隐形成本

禁止使用：未来未揭示manifest、轨迹验证后才得到的精确最小间隔、当前待构造轨迹的精确能耗、最终CP选择、未来落地结局、实验seed、飞机ID大小、方法名称作为策略捷径。

已有且在决策前有效的数值缓存结果可以使用，但必须记录可用性和来源时间；不能为获取特征而先调用目标昂贵函数，再声称模型省掉了该调用。

保留对象内关联，不能仅以SOC均值、相位均值、空槽总量代表全场。资源竞争不限于空间最近邻：相距很远的飞机也可能争同一pad。

### 6.3 已冻结的小模型

首轮仅训练一个CPU候选条件集合MLP，使用64维对象嵌入、两层共享编码器；具体结构、归一化和训练参数见第19节及配置。保留飞机、槽位、pad和预约区间各自的集合，而不是将整个空域压成几项平均值。

本机/候选编码＋候选条件的飞机集合编码＋资源区间编码，输出相对优先分数。集合聚合必须在对象编码后进行，并传递数量与mask。Deep Sets只是表征设计参考，不是本场景效果保证。[L2]

不同时训练树模型、GNN或Transformer，不引入在线自动选模型。本轮框架可保留可替换接口，但结果只对应这一种已冻结模型。OFF与普通Stage2运行不得强制导入训练框架。

## 7. 学习目标与损失：先学习计算优先，不直接模仿某架飞机必须飞

### 7.1 最基本的三类输出

1. `priority_score`：给定状态与已观察搜索结果，某描述下一步值得计算的相对分数。
2. `proposal_outcome_prediction`（辅助；缺失标签时mask）：预测该工作能否生成单机有效候选；不是SAFE授权。
3. `compute_cost_prediction`（辅助；缺失标签时mask）：预测生成/验证成本或工作量；时间标签必须带硬件和缓存状态。

不建议仅优化“可行候选数量/秒”：它会偏向便宜但没有调度价值的重复候选，也可能放弃唯一能救急的昂贵分支。成本在排序中的权重或约束必须公开，不能自动压过重要分支覆盖。

### 7.2 首版采用离线监督分组排序

学习有证据的工作偏好，采用分组pairwise ranking；辅助单机有效性和成本回归用于诊断，不直接覆盖priority排序或安全判定。不同质量分量按绑定目标的词典序及既有数值比较规则生成偏好，不暗中用任意权重压成一个reward。

本轮pairwise损失：

\[
\mathcal L_{rank} = \frac{1}{|P|}\sum_{(u^+,u^-)\in P}\log\{1+\exp[-(s_\theta(u^+)-s_\theta(u^-))]\}.
\]

偏好对须来自同一可比状态/父节点与相同参考评价规则；无可比标签时mask。该损失学习相对顺序，不输出物理保证，不等于Q*或长期最优价值。

辅助任务必须按有效标签mask计算。本轮loss权重、采样与停止规则固定于第19节和YAML，不根据测试结果反复调权。辅助头没有有效标签时该项loss置零并记录缺失，不能拿伪造标签填满batch。

### 7.3 为什么不以旧CP输出直接做唯一标签

当前CP在中等场景不优于Slack，且优化的是有限候选预测值。旧代码还有向内推进尾部评分偏差。复制旧CP最终被选候选，会把这些偏差一起复制，不能被称为“学习较优调度”。[R1,R2]

新Stage2目标稳定前，可采集物理事实、成本及候选谱系；质量偏好权重的正式训练和闭环比较绑定一个明确的新目标版本。无须等待Stage2在全部场景获胜，但需要其实现语义自洽。

## 8. 数据：原始事实先存，目标标签后生成

### 8.1 数据单元

以决策快照与候选生成事件为中心，而不是把每个0.2秒物理帧都当独立样本。

每次构造事件记录：快照ID与血缘、就绪描述集合或可恢复的枚举游标、父链ID、实际选择、选择概率（有随机探测时）、廉价特征、构造阶段、缓存命中、真实结果、拒绝/未知原因、wall/CPU与工作量计数、生成列ID、最终被选/提交情况及已验证目标向量。

需要记录前后的成本边界；候选失败、超时、未尝试都保留，不只存成功轨迹。只读日志不得包含可调用对象，不用任意pickle作为跨环境接口。

### 8.2 标签必须分层

| 记录 | 标签解释 |
|---|---|
| 明确动力学/能源违规 | 此描述在此源状态下的单机不可行证据 |
| 单机验证通过 | 只证明单机条件；不证明能与其他决策联合执行 |
| 与固定承诺冲突 | 此快照背景下不兼容，不是永久几何不可行 |
| 联合方案通过 | 这个组合通过，不表示每个元素在任意组合都安全 |
| UNKNOWN/预算耗尽/未尝试 | 缺失或截尾；不能编码成负类 |
| 有效但未进入最终方案 | 未被选择；不能直接编码成“无价值” |
| 执行后成功/失败 | 特定策略与未来需求下的结果；不是别的候选的反事实标签 |

### 8.3 质量偏好参考：有限观察中的较好方案集合

在少量固定快照上，用同一目标和原验证器生成一个有限、较丰富的目录，同时运行独立Slack与CP，最多保留8份不同的已验证方案及平局方案。首轮不额外引入未批准的近优质量容差。它是`bounded_reference`，不是全局oracle。

记录生成这些方案的描述谱系。参考方案中使用的构造分支可以获得正支持；没有被选中的有效分支只能记未支持或弱标签，不能自动强负。早期转移分支的标签应关联其后继完整链，不能拿内环final的短期落地回报压低所有外环扩展。

默认标签规则见第19.4节：在少量分支上做有界、同目录的条件再求解，只称“已观察到的条件偏好”，不称真实全局边际价值。每快照最多8次，每次含验证最多5秒，计入该快照及全局额度；不要求每个候选跑完整episode。

单一最佳方案会有偶然平局和互补分支，首版优先使用多解支持与目标分量，不使用“最佳叶祖先=1，其余=0”的硬标签。

### 8.4 选择偏差与有限探索

只记录传统顺序已经尝试的描述，会遗漏被它跳过的区域。离线标注按固定20%的工作机会加入分层随机探测，覆盖不同环、目标、即时/延后、完整链/部分链，所有结果仍通过原后端。

随机探测仅在离线副本中执行，不改变真实飞行。未探测区域不宣称已覆盖。保存抽样规则及概率；不知道倾向概率的数据不冒称已完成无偏离线评估。

学习改变搜索或运行状态后，分布也会变化。首版保留新增日志接口，但不自动启动第二轮采集或再训练。DAgger提供的是分布变化问题的参考，不是本阶段必须运行的算法。[L4]

## 9. 训练/验证划分与历史数据使用

已经反复查看的seed71及其续跑、策略分支全部属于开发资料；可用于接口与小样本拟合自检，不得进入本轮正式训练、验证或留出测试。开发拟合使用临时权重，正式训练必须重新初始化。

同一episode、同一checkpoint祖先、相邻时刻和从同一父状态产生的策略分支放在同一血缘组，不能随机打散候选行后称测试独立。标准化、标签选择、模型早停仅用train/validation；test评价在模型冻结后进行一次，不用于调整参数。自动化可在采集阶段预先生成test事实与标签，但必须封存，训练和人工调参不可读取其结果；只有预先声明的root身份与场景类型可用于安排试验。

本轮目标收集24个独立状态根，16个train、4个validation、4个test。优先使用版本兼容、未曾参与模型选择且具有完整来源的独立状态；不足时，调用现有合法初态生成器，以新seed构造当前已经存在的18/24/36架三类场景，不修改物理、SOC或服务分布。具体seed及场景轮转规则在`stage3_dataset_plan_v1_0.yaml`中固定。

这些状态根主要用于初步监督和接口验证，不等价于24次完整episode，也不足以证明长期泛化。没有真实推进经历的初态必须标记`SYNTHETIC_INITIAL`，不得伪造在途承诺或声称来自后期拥堵回放。预算内能获得的真实运行状态另标来源；同一root只能属于一个split。

最多从旧seed71抽取18个开发快照；只读抽取已有文件，不为补齐它们重新跑长episode。历史3个FAIL回放不得改写为PASS：只使用可核对的原始状态/事件/能源事实，涉及漏帧的标签排除；混合v6/v7前缀不得混成同一新策略数据。

数据不足不触发追加预算。若有效偏好对为零、没有独立训练与验证组，标记`DATA_INSUFFICIENT`，交付基础架构及事实日志；仅有少量标签则允许完成一次小试，但明确证据不足，不人为补负类。模型的训练、验证损失和各环/阶段召回必须报告；不以训练loss下降代替在线收益。

## 10. 运行模式、保留覆盖与回退

### 10.1 已批准模式

| 模式 | 行为 |
|---|---|
| `OFF` | 原Stage2路径，不加载模型 |
| `RECORD` | 原行为加有界事实日志，记录开销 |
| `SHADOW_OFFLINE` | 从保存的快照与描述打分，不改变原时钟、缓存或世界 |
| `GUIDED_ORDER` | 在相同候选额度内重排就绪工作，用于同状态诊断 |
| `GUIDED_LIMITED` | 在一半候选构造额度内使用学习顺序，本轮唯一学习闭环模式 |

主程序默认保持OFF。通过基础防护和数据检查后，由本轮专用runner依次启动shadow、训练和小范围guided试验；不再请求D1—D7审批。模型不可用时不以随机网络进入闭环。

### 10.2 预算与共同覆盖

较低预算取所绑定Stage2的`candidate_seconds`、`max_per_aircraft`与`max_attempts`的0.5倍，整数向下取整且至少1。CP时间、hint时间、最终验证、正常规划软时限和看门狗保持绑定版本原值；这些共同成本不隐藏到候选之外。当前设计审查版本对应12→6秒、64→32次/机、2048→1024次/决策；若实际Stage2已更新，使用运行绑定中的真实值，并在启动前生成resolved配置。

较低预算的非学习对照与学习方法使用同一工作空间、同一目录容量、同一覆盖机制和同一额度。未被物化的描述仍是未尝试，不能记为物理不可行。首轮不学习停止阈值。

KEEP、WAIT、承诺和安全依赖不能删除。保留Stage2的完整链/部分链、目标与延后启动多样性规则。先按O/M/I轮询、环内能源余量顺序，为每架可决策飞机提供至多一次传统首选工作机会；没有额度时明确记录未覆盖，不宣称保证每机找到移动方案。随后采用3次学习选择＋1次原启发式选择的固定交错。子工作只有真实父链生成后才能就绪。

候选额度前80%按上述策略执行，后20%作为共同的确定性继续/回退区。非学习对照使用同样的阶段划分和覆盖顺序；学习异常发生后用剩余额度继续原顺序，不重新启动计时，不恢复到完整12秒等参考额度。模型未异常时，后20%也按原启发式继续，避免为“保留预算”无故停止。

### 10.3 回退边界

版本不符、输入超出模型声明的实体数量或数值范围、NaN、非法ID、缺少模型、推理异常时回到确定性顺序并记录原因。候选条件集合的排序输出必须是当前ready描述的合法排列；不能注入新动作。

本轮不使用未校准的“模型置信度很高”来跳过安全或扩大额度。没有可提交新动作时使用仍有效的已承诺执行并继续共同应急机制；KEEP不是无限能源安全保证。

恢复成本计入当次调度。不能先计算完整旧基线保底，再把它的成本排除；不能承诺有限回退必然恢复完整目录质量。在线通常不知道“遗漏了更好方案”，不得设计依赖这个不可知真值的自动回退条件。

## 11. 末端价值接口：可预留，暂不混入主实验

预留接口为：

```text
TailEstimator.predict(revealed_snapshot, joint_tentative_plan, horizon)
    -> remaining_energy, remaining_wait, event_risk_estimates,
       missing_masks, uncertainty_metadata, model_version
```

若以后训练，应学习共同确定性下游估计的残差或直接观测的后续代价分量；不能一开始就把所有含义压成一个奖励数。

多个飞机共享六pad，联合尾部价值通常不等于独立单机值之和。除非明确采用并验证可加近似，否则不能把独立网络分数直接相加塞进CP线性目标。后续可比较少量联合方案再排名，或设计有资源耦合的近似结构；这是另一个实验模式。

价值标签需要未来观察，但部署输入只能含当时可见状态。允许用独立未来实现产生监督结果，不允许把该未来manifest喂给策略。对未完成/失败/分流的结果分别编码，不能把截尾样本记为零剩余能耗。

已执行历史只给出原策略的一个结果，不能凭空赋给未执行方案。对比动作的价值标签需要有限反事实分支、同一后续策略和受控需求，或采用明确的离线估计假设。

该接口本轮固定关闭，不训练、不参与评分；不声称候选加速模型已学会长期拥堵。

## 12. 与Stage2持续修改的协作

开发边界：Stage2只维护共同后端、评分和候选空间；Stage3新增独立包及少量挂钩。不要在`stage2_planning.py`内直接堆训练代码、网络权重加载和实验数据处理。

阶段开始先输出一页映射表：实际接口、可复用部分、需要新增的挂钩、目标变化影响。每次合并后更新指纹与测试，不为保住旧训练结果阻止Stage2修正目标。

为避免旧偏差传入新模型，正式质量标签生成绑定一个Stage2快照版本。Stage2可继续在另一分支修改，Stage3用显式适配或重标注跟进；不要求整个项目停止开发直到最终论文版本冻结。

## 13. 首轮训练与最小试验

### 13.1 一次CPU训练

只训练一个候选条件集合MLP，使用第19节的固定参数。数据目标24个独立状态根，不追加大型模型矩阵、网格搜索或“训练到获胜”的循环。可运行一次临时开发拟合自检，最多100梯度步，正式模型必须重新初始化。

首次正式训练使用独立train/validation。若Stage2目标在数据收集前已改变，记录新目标并依此标注；如果训练中发生变化，本轮继续使用已经绑定的版本，不自动热切换到新目标。基线可以在另一个分支继续改善，不要求它停止开发。

### 13.2 同快照最小比较

在最多6个兼容的快照上比较三种方式，至少2个来自留出test；没有足够独立test时标记`LIMITED_EVIDENCE`：

| 方式 | 候选额度 | 排序 | 用途 |
|---|---:|---|---|
| `reference_full` | 绑定基线的1.0倍 | 共同传统启发式 | 有限质量参照，不是oracle |
| `heuristic_reduced` | 0.5倍 | 共同传统启发式 | 排除“仅缩预算就能提速”的解释 |
| `learned_reduced` | 0.5倍 | 学习＋确定性覆盖 | 测学习增量 |

三组均使用相同的资源/目标/验证/CP设置。候选物化结果可以不同，这正是前端加速问题；不得提前为学习组生成完整目录。每组每快照运行一次，方法顺序按快照编号轮转，不反复跑到取得好数值。输入源和已有有效缓存可一致复制；额外参考计算不得把新缓存注入另一组。

真实计时需重新运行物化过程，不将已知标签或事后能耗直接当成在线缓存。输出完整成本和目标向量，不只报网络速度或排序准确率。

### 13.3 一个60秒闭环

模型冻结后，从预先选定的独立中等test状态开始，`heuristic_reduced`与`learned_reduced`各推进60仿真秒一次。新请求使用同一物化manifest，策略只能读取已经揭示的请求。主机使用同一物理CPU核心、同一线程数、相同冷/暖缓存条件；默认串行运行两组以减少争用。

默认选择dataset计划中第一个中等test根；若该根不合法或缺失，按冻结test顺序选择下一个中等根，禁止看结果选场景；无合格中等根则标记`EVALUATION_INPUT_MISSING`而不换成训练状态充当测试。

既有可视化平台显示学习推荐、实际尝试、已验证候选和最终提交的区别；记录正常/应急/失败/未完成、总能耗及各环holding耗能。60秒只说明接入与初步成本，不证明长期质量或无失败。没有600秒/完整清空追加任务，也不增加第三个完整闭环组。

## 14. 计时、评价与不能夸大的结论

### 14.1 完整在线计时

\[
T_{normal}=T_{snapshot}+T_{descriptor}+T_{feature}+T_{inference}
+T_{materialize}+T_{validation}+T_{CP}+T_{commit}+T_{fallback}.
\]

按互斥边界统计，不能将嵌套计时直接求和。共同应急/准入的完整dispatch时间另报。仿真执行与离线标注训练成本也另报，不混成网络推理或solver时间。

冷缓存与暖缓存分别注明，禁止基线冷、学习暖。已采样候选日志上的离线回放不能还原全部新调用与缓存成本，因此不是真实加速证据。

### 14.2 首轮指标

模型侧：有效候选/重要分支覆盖、各环/阶段召回、成对偏好一致性、缺失与OOD比例。若训练了概率头，报告可靠性而不把softmax大值直接称可信证书。

求解侧：昂贵构造与验证次数、有效完整链覆盖、最终已认证目标向量、空提交/回退、完整正常规划P50/P95/最大值、超时。

系统侧：正常/应急/总接地、能源失败、分流、未完成、总能耗与各环holding耗能。不会因60秒中零失败就宣称长期安全，也不因分类精度高就宣称加速。

首轮不预设“必须快10%”或训练至胜出的门槛。D7已确认：本轮没有授权用少落地、多失败或更多应急换取速度的质量退化额度。所有差异按向量如实报告；出现退化时标记`QUALITY_REGRESSION_OBSERVED`，不能写成质量保持或自动通过部署。

若小窗口未观察到退化，只能表述“该窗口内未观察到”，不视为已经证明非劣。结构性安全/事务错误立即停止对应试验；学习效用不成立则正常结束本轮并报告，不扩预算、不重新调参。

## 15. 小规模针对性测试

只增加以下必要检查，复用Stage2测试，不重造几十项物理资格矩阵：

1. OFF不加载模型；RECORD不修改物理状态/资源；固定工作额度回放保持传统候选顺序。真实wall预算下的日志抖动单独记录，不能伪称字节完全一致。
2. 特征提取不得调用本应被省掉的轨迹生成、精确能耗或完整冲突验证；用调用桩断言。
3. 相同飞机集合重新排列、ID重命名后，按对象映射的评分应一致；目标资源身份仍保留。
4. 未揭示需求、seed、最终结果和未来决策不可进入输入；标签文件与部署特征物理隔离。
5. 子描述必须依赖真实已构造父链；不把未验证节点当可执行状态。
6. UNKNOWN、超时、未尝试和未被选择不能自动变成负类；无有效标签batch可跳过并记录。
7. 不匹配指纹、非法ID、NaN与模型故障触发共同确定性回退，不产生未认证动作。
8. 即时转移、上游延后、不同pad以及唯一可行稀有分支均可被传统覆盖机制取到；模型不能硬删除KEEP/WAIT或承诺。
9. 两架飞机竞争一个pad时，模型高分不能使最终资源冲突通过；最终检查覆盖整个已承诺机动。
10. 相同血缘不能跨train/validation/test；续跑和策略分支保持分组。
11. 特征、推理、恢复和最终验证全部进入真实在线计时；同预算对照存在。
12. 既有回放可查看尝试顺序、接受/拒绝、等待位置、落地与能耗；模型提议和真正提交的动作视觉上区分。

测试通过表示接口和防护可用，不表示学习有效。人工观察状态如实保留，不自动填PASS。

## 19. 本轮冻结工程参数与执行细节

本节将D1—D7细化为一套小试默认值。它们可以在未来版本修订，但本轮不得在查看test或闭环结果后改动。结构规则以正文为准；数值以配套YAML为唯一机器事实源；二者不一致时停止启动并修正文件，不任选一个解释。

### 19.1 绑定实际Stage2，而不是强行回退历史提交

S3-A生成`run_binding.generated.json`和`resolved_config.generated.yaml`，写入真实commit、工作区差异、Stage2目标/末端估计、物理/数值/应急/失败/候选策略、所有输入hash、环境依赖及线程配置。没有显式版本号的语义，用相关源文件和配置hash生成稳定标识；不能用一个固定“latest”字符串替代。

一次数据—训练—评价使用同一个绑定。Stage2正在修改的下游估计可以先合并后绑定；也可以与Stage3在隔离分支并行推进。本合同不宣称该改动已实现，也不要求其必须胜过Slack才允许试验。无法导出一致的目标向量或候选接口时，先交付接口和记录，不伪造质量标签。

依赖优先复用服务器现有环境，记录实际版本，不在本合同中虚构已安装版本或强制升级公共仿真依赖。CPU训练；单个评估进程、CP与推理各1线程，DataLoader workers=0；离线独立标注进程最多2个，禁止嵌套开启更多线程。权重文件不随本文件包预置。

### 19.2 模型、特征与训练参数

采用四类对象集合：飞机、旋转槽位、六pad、预约区间。每个对象在编码前绑定候选关系特征：相对相位/距离、是否本机/目标、是否共享目标资源、时间区间相对位置，以及相关能源与承诺信息。对象标识仅用于建立关联和稳定平局，不作为数值捷径。

每类编码器为`Linear → ReLU → Linear → ReLU`，宽度64；本机/描述查询同样为64维。每类集合做带mask的mean和max聚合，并附归一化数量；与查询及搜索上下文拼接后使用128、64两层ReLU评分头。输出priority原始分数、单机有效性logit和`log1p(cost_ms)`预测。模型不输出轨迹系数或可行性授权。

首版无循环网络、注意力、dropout或BatchNorm；特征标准化使用固定物理尺度后，在train上拟合均值/标准差，validation/test只应用。missing值填0并提供mask；空集合的mean/max为0且count=0。模型浮点使用float32；物理与验证仍用原后端精度。模型参数量应不超过250000；若适配导致超限，记录架构错误，不静默扩大网络。

实体上限为256架飞机、128个槽位、16个pad、1024条预约。超限时回到确定性顺序，不截断交通数据；这些是模型输入资格范围，不改变场景容量。稳定物理尺度包括：长度900m、速度25m/s、加速度1.5m/s²、时间为绑定预测时域、功率100kW、能量使用绑定模型的等效容量；不同量必须保留语义字段。

正式训练：随机seed=20261023；AdamW，学习率0.001、weight decay=0.0001；最多30个epoch；每batch最多16个上下文组、每组最多64个有效偏好对；梯度范数裁剪1.0；验证指标连续5个epoch不改善即停止。只进行一次正式训练，用验证主排序loss最低的checkpoint；无有效排序验证标签时不得用测试集替代早停依据。

损失为`L_rank + 0.1 L_valid + 0.1 L_cost`。主排序使用softplus pairwise loss；单机有效性用带mask的二元交叉熵；成本用`log1p(ms)`目标的Huber loss。各项先按上下文组平均，再按batch平均，避免高密度状态凭行数压倒其他状态。成本头仅辅助表示与报告，本轮不将预测收益/成本比作为新的部署排序公式。

### 19.3 特征成本与预算约束

`FeatureEncoder`不得调用轨迹生成、能量积分、全轨迹分离检查或CP。已存在、有效且在决策前可用的缓存结果可以读取，须记录是否可用；训练时也只能使用当时可用的缓存字段。Stage2的轻量下游估计由共同接口供给并计时，缺失时mask，不用神经模型补造目标代价。

推理前就绪批次最大64。每次排序后最多消费8个描述；候选覆盖或父链变化使特征失效时提前刷新。枚举成本、集合编码、推理、覆盖选择、回退与验证全部计入完整正常规划时间。不能另开不计时进程先算候选或特征。

### 19.4 标签生成的确切规则

每个快照参考计算硬额度180秒，包含目录扩展、确定性验证、Slack/CP参考以及条件再求解，且服从全局预算。参考目录最多采用绑定基线2倍候选工作量，候选阶段wall最多30秒；仍然是有限参考，不是全搜索。

数据分三层：

- **物理事实层**：明确单机有效或违规可作辅助有效性标签；固定背景冲突另存，不能混为单机永久不可行；UNKNOWN、未尝试与超时mask。成本标签只用已完成的实际调用，超时成本标记截尾，不当精确时长。
- **参考支持层**：保留最多8份已认证且互不相同的联合方案，保存其工作描述祖先集合。被支持分支为“观察到有贡献”，其余有效分支仍是未支持，不直接设负类。祖先归因表示支持某个后继，不等于该父分支必然优秀。
- **主偏好层**：只在同一决策上下文、可比父节点/阶段下建pair。允许“参考支持分支优于明确单机违规分支”；也允许在同一候选目录、相同预算下，对两个分支分别要求至少选择一个已生成后继列，取得已认证组合后，按共同目标的实际向量形成严格观察偏好。无可行incumbent、UNKNOWN或预算中断不能视为劣解证明；完全平局不建强pair。

条件再求解每快照最多8次、每次含验证最多5秒。它产生的是有限搜索中观察到的偏好，不是全局价值顺序；互补分支应在相同背景下比较，不能用两个不同未来实现作标签。新增评分不得直接把参考方案被选频率当唯一真值。

随机探测固定占离线物化机会的20%，在环、即时/延后、目标类型和深度上分层；采样使用独立固定seed并记录概率。线上不进行这些离线探索。未产生有效pair时保留事实数据，但不以伪负类强行训练。

### 19.5 4小时总预算

新增自动计算总额度14400秒，从本轮自动化preflight启动开始累计；恢复运行不清零。人工编辑代码时间不占额度，自动测试、生成、标注、训练和评价均占。并行按实际campaign wall计入，同时报告完整进程树CPU；最多2个独立进程，不用更多核心暗中扩规模。

| 阶段 | 最大自动wall额度 |
|---|---:|
| preflight与针对性测试 | 900秒 |
| 数据与有限参考标注 | 7200秒 |
| 一次CPU训练 | 1800秒 |
| 同状态评价与60秒成对闭环 | 3600秒 |
| 归档与报告 | 900秒 |
| 合计 | 14400秒 |

各阶段额度不自动扩展，提前完成的余额保留，不用于新增模型、seed矩阵或长episode。达到累计13500秒停止新增计算并归档；任何阶段到额度也保存部分结果、标记`BUDGET_LIMITED`。非可中断原子调用记录实际超时，由父runner在硬截止终止未提交的离线任务；不能发布部分模型或部分资源事务。

若3600秒评价额度不足以完成两组60秒，分别保存到已完成的共同事件/检查点边界，报告真实推进长度；不得悄悄减少交通或调高SOC。没有可比较共同窗口时只交付同状态结果，不声称闭环验证完成。

### 19.6 运行与科研结论分开

交付状态至少含：`IMPLEMENTATION_NOT_RUN`、`INFRASTRUCTURE_READY`、`DATA_INSUFFICIENT`、`TRAINED_PILOT`、`EVALUATION_PARTIAL`、`BUDGET_LIMITED`、`QUALITY_REGRESSION_OBSERVED`等事实状态，以及独立的`LEARNABLE_SIGNAL_NOT_ESTABLISHED/OBSERVED`和`ONLINE_BENEFIT_NOT_ESTABLISHED/OBSERVED`。没有自动性能“通过”阈值。

测试数据只能在模型冻结后评价一次，失败的结果照实保留；本轮不根据其表现换网络、改损失、改覆盖比例或重训。后续要继续研究可以另开版本，但不得覆盖首轮负结果。
