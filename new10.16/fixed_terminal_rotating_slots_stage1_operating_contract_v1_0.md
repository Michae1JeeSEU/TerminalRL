**合同编号：FT-RS-S1-1.0**  
**版本：v1.0｜规范状态：FORMAL_FOR_IMPLEMENTATION｜日期：2026-10-16**  
**实施范围：场景搭建、接口、确定性执行、正确性验证、既有可视化平台验收。**

本合同及配套YAML替代v0.9。所有研究选择和必需运行参数均已固定，不需要再次征询参数选择。**规范已冻结不等于代码已经实现，也不等于验收已经通过。**实现者必须完成下述自动测试、数据重放和研究负责人可视化验收，才能宣布第一阶段完成。

## 1. 研究范围与禁止的隐式扩展

单一机型、质量、电池和运动包线；仅SOC、服务类别、到达时间、入口和当前状态可以不同。集中式调度器获知当前全部受管状态。无风、无定位误差、无建筑、无噪声/禁飞扇区。地面为水平面，坐标原点海拔0m。

仅研究到达，不研究离场流、充电、地面滑行冲突、运营机队循环、异构机型、姿态内环、旋翼失效或通信随机丢包。正常环间动作不允许跳环、同环换座、协同换位、向外避让或反向盘旋。**应急直达pad是唯一正常拓扑例外，不意味着所有飞机可以自由三维飞行。**

服务结束表示飞机经本研究抽象的地面清空流程退出到达系统。不能把它解释为免费起飞或立即生成满电新飞机。所有正常和应急机动遵守同一80m间隔；应急不是豁免安全。

## 2. 坐标、几何、旋转槽位与容量

### 2.1 坐标和单位

使用ENU局部坐标：x东、y北、z上；z为AGL，平地海拔0m，因此本版本数值上AGL=MSL。内部采用SI单位；角度计算用弧度；SOC∈[0,1]。分别记录水平速度、垂直速度和三维速度模长。能量用J，输出kWh除以3,600,000。禁止把角速度当成线速度。

### 2.2 固定几何

| 对象 | 半径/m | 高度AGL/m | 槽位/资源数 |
|---|---:|---:|---:|
| 四个外部准入入口 | 900 | 110 | 4 |
| Outer | 600 | 110 | 37 |
| Middle | 450 | 70 | 28 |
| Inner | 300 | 30 | 18 |
| pad布局圆 | 100 | 0 | 6 |
| 每个pad上方垂降衔接点 | 与pad相同x/y | 15 | 每pad一个 |

受管空间为`r≤900m, 0≤z≤120m`。三环全部顺时针，公共角速度幅值`omega=0.035rad/s`，初始相位全部为0。

| 环 | 线速度/m·s⁻¹ | 向心加速度/m·s⁻² |
|---|---:|---:|
| Outer | 21.00 | 0.73500 |
| Middle | 15.75 | 0.55125 |
| Inner | 10.50 | 0.36750 |

周期`2π/omega=179.519580s`。上述尺寸、速度和槽位数是冻结的研究配置，不声称取自某篇论文的完整标准场景。对既有研究只借鉴结构，不混用其机型、质量、速度与高度。[S3、S4]

### 2.3 槽位轨迹

对于环r、第k个槽位：

```text
theta_rk(t) = 2*pi*k/M_r - omega*t
q_rk(t) = (R_r*cos(theta_rk), R_r*sin(theta_rk), H_r)
```

必须由绝对仿真时钟计算，不能在重规划、转移完成或恢复checkpoint时重置相位。稳定占位飞机精确跟踪该移动参考位置及其速度、加速度，不调整速度/相位。

同角速度使任意两槽位的相对角度恒定。仅等待不改变两个指定槽位的相对几何；机会变化来自占用释放、在途机动、固定地面pad以及新请求。不得通过错误时钟制造相位滑移。

### 2.4 80m安全阈值与100m槽位布局的区别

**80m是唯一运行安全阈值。100m只用于保留已经接受的槽位数量，不是新增的候选安全限制。**

均匀槽位数按`floor(pi/asin(100/(2R)))`推导。相邻实际弦长为Outer 101.7671m、Middle 100.7680m、Inner 104.1889m。相邻环稳定飞机最小中心距下界为`sqrt(150²+40²)=155.2417m`。

这些结构下界仅覆盖稳定盘旋，不能证明转移安全。83是环槽位总数，不是空中总数上限，也不是吞吐量。不得静默继承`max_active=60`等历史计算上限作为物理容量。若硬件资源耗尽，应记软件运行失败，不能伪装成满载分流。

### 2.5 pad位置

`p_j=(100*cos(j*pi/3),100*sin(j*pi/3),0), j=0...5`。相邻pad中心100m。不同pad允许同时下降/服务，但进近轨迹仍须独立检查。没有全终端单飞机着陆锁，也没有按pad编号就自动免检的规则。

## 4. 持续请求、初始SOC、准入与分流

### 4.1 需求与可见信息

每个请求固定`id, release_time, gate_id, initial_soc, service_class, vehicle_profile_id`。四门角度为0、π/2、π、3π/2，各概率0.25；每次请求只抽一次，不能换门重试。

正常SOC使用**截断正态**`N(0.75,0.08²)`，截断区间`[0.60,0.90]`，不是裁剪后在边界堆积概率。分布属于DESIGN，不声称为真实到达电量数据。入界后的SOC只可自然消耗；拒绝准入不得重抽SOC。低SOC、临界和不可挽救状态只出现在明确命名的失效测试fixture，不混入常规需求。

随机诊断使用泊松到达过程，即指数分布间隔，速率60/120/180架/小时。它们仅为固定诊断强度，不预先宣称对应某个饱和等级。需求窗口3600s，之后停止新请求并继续清空，最长追加1800s。默认空场启动；高占用作为独立fixture。随机诊断seed固定为11、23、47、71、101。

预生成完整需求清单用于重放，但调度器只看到已经揭示的请求和当前全局状态，不能读取未来随机序列。

### 4.2 入界初态

请求在900m、110m处；初始水平速度21m/s，无垂直速度，初始加速度为0。速度方向为单位内向径向与单位顺时针切线之和归一化，即各占45°。上游轨迹在模型外，此初态不能在已经存在的飞机身上以瞬时转向实现。

### 4.3 准入规则

请求必须在成为受管空中实体之前取得一个**立即开始**的合法入口→Outer槽位机动。检查初态、全程可达性、安全、目标预约、以及完成入场机动的正剩余电量。还必须通过单机无交通正常到达参考的储备筛查：其计算不能证明全机群将来都能落地，但可拒绝明显初始能源不足的请求。

不再要求全机群联合备用完成方案，不再以“已证明所有飞机都永不耗尽”为准入条件。这是对v0.9的明确删除。

无法获得入场机动时立即分流；不在门口悬停，不直接出生在空槽位，不在本终端重试。有限候选没找到方案记`NO_PLAN_FOUND`，只有经过证明才能记`PROVEN_INFEASIBLE`。分流原因分别包含外环无可预约槽、入口/交通冲突、动态不可达、初始能源筛查不通过、验证UNKNOWN、计算未找到。

即使Middle/Inner有空位，只要Outer无法接纳，也不能跳环入场。若Outer当前满但某次已承诺离开会在入场机抵达前清空，允许验证未来空位；不要求目标此刻FREE。

### 4.4 分流与外部边界

```text
reroute_cost = 600 equivalent-delay-seconds/request
C_reroute = 600 * N_rerouted
```

分流成本计一次，计入全部原始需求的性能；不是实际外部航程或kWh。外部可分流成功是边界假设，不由本终端证明。已经入场的飞机不得因拥堵或低SOC被删除成REROUTED。

为了避免算法通过选择性拒绝提高平均值，必须同时报告offered、admitted、rerouted及全部需求口径指标；禁止只报告成功飞机的平均效率。

## 5. 状态、预约和唯一占用

### 5.1 飞机状态

```text
REQUESTED → REROUTED
REQUESTED → INBOUND → HOLD_OUTER → TRANSFER_O_M
          → HOLD_MIDDLE → TRANSFER_M_I → HOLD_INNER
          → FINAL_NORMAL → VERTICAL_DESCENT → LANDED_SERVICE → CLEARED
HOLD_{任意环} → FINAL_EMERGENCY → VERTICAL_DESCENT → LANDED_SERVICE → CLEARED
```

应急标志可在活动转移期间触发，但只能在当前机动完成后启动应急直达；活动INBOUND必须完成至Outer。不存在中途换目标或隐式打断轨迹。正常/应急final已经覆盖到接地，不再在15m另做资源决策。

### 5.2 槽位权威事实源

采用时间预约表，不用一个布尔值替代时间信息。UI显示FREE、RESERVED、OCCUPIED、DEPARTING；底层记录实体占据、未来承诺和源清空保护。同一槽位可有多个不重叠预约。

源槽位在飞机离开后，直到其未来轨迹与源移动参考点不再进入80m邻域时才清空；清空条件须覆盖至该机动结束，后续稳定目标也必须安全。新使用者仍须检查其实际轨迹与离开飞机，而非只检查槽位中心。

目标预约从入位保护开始直到承诺离开完成清空；没有承诺离开时，默认持续占用。软计划中的预想离开不是真实FREE。物理实体、源保护、目标预约分开计数；转移飞机只计一架。

### 5.3 软计划可改，但不能破坏已经依赖它的机动

未开始的未来动作原则上可修改。唯一依赖条件是：**不得让已经执行的入场/转移/进近失去其被证明安全的资源支持。**若一个已开始入场依赖未来源占据者离开，则那项离开必须保留，或被一个提供等价安全释放的动作原子替代。

这属于局部资源依赖，不是把三环全部航程锁死。UI和日志必须列出这种依赖，不得出现“名义上软预约，事实上不可改却不说明”。取消和替换必须事务化；不能先删旧承诺再尝试新方案。

## 6. 时间与决策触发

### 6.1 正式时间配置

| 项目 | 固定规则 |
|---|---|
| 执行状态最大步长 | 0.2s |
| 能源积分最大分段步长 | 0.2s；可内部自适应细分 |
| 常规调度心跳 | t=0,5,10,…s |
| 事件触发 | 新请求、入场/转移完成、源槽位清空、pad服务结束、应急触发、承诺失效/求解迟到 |
| 事件合并 | 同一精确时刻的所有事件先结算，再只调用一次联合决策接口 |
| 应急状态监测 | 每个执行步及精确事件，不等5s心跳 |
| 默认预览 | 240s，不是硬路线或安全截断长度 |
| 承诺长度 | 当前机动启动至完成，随轨迹而定 |
| 回放采样 | 0.2s＋全部精确事件；显示渲染帧率独立 |

**没有任何规则要求每1s无条件运行完整调度。**单纯推进时间、相位和SOC不构成每步全量重搜理由；但应急监测不能被省略。

实现可以安排未来5s内的启动事件；这些动作启动前仍可按第5.3节原子修改。若不提前安排，飞机可在下一次心跳或事件继续申请，不强制等待整数圈。临近pad机会也可作为已经安排的启动事件，不必靠细化物理步长碰巧捕获。

### 6.2 解析推进与数值采样分离

稳定圆周运动解析计算；已批准轨迹在任意t查询。0.2s是状态输出及积分分段上限，不是把机动折线化的许可。连续安全验证覆盖两个步长之间；不每0.2s重新生成轨迹、重新搜索全部候选。

精确事件可落在0.2s网格之间。touchdown、服务结束、槽位清空、SOC耗尽都定位到事件时刻，不四舍五入改变结果。安全需检查整个承诺及必要连接，不能在240s结束时把飞机当作消失。

### 6.3 时延模式

第一阶段功能验收使用明确的零模拟计算时延，记录真实CPU用时但不声称实时部署。另有强制的0.2s、1.2s、5.2s迟到注入测试。时延期间当前轨迹、保持、SOC、槽位和服务时钟持续推进；迟到命令必须重新验证，禁止从旧起点瞬移执行。

未来算法的实际wall-clock预算不在本合同规定。阶段一不得为了模拟一个尚未选择的优化器，偷偷添加随机求解失败。

## 7. 可执行轨迹与无悬停规则

### 7.1 权威计划

计划提供连续`p(t),v(t),a(t),jerk(t)`，含轨迹hash、profile hash、源状态版本、开始/结束、目标槽位或pad、功率历史和资源依赖。**checked == committed == executed**。修改参数化、速度、结束时间或轨迹都必须形成新计划并重新验证。

几何曲线不能直接交给执行器。节点位置一致但速度或加速度跳变不合格。

### 7.2 正常相邻环转移

起点匹配当前槽位的位置、速度、加速度；终点匹配目标槽位在**未来到达时刻**的位置、速度、加速度。半径、高度非增；角向顺时针不逆行；水平速度≥2m/s。不同目标并非必然可达；返回未找到不能变成强行转移。

正常拓扑只允许Outer→Middle、Middle→Inner。没有0/π固定切环门。实现必须通过非门角度37°及133°的成功转移fixture。

### 7.3 入场和最后进近

INBOUND在r∈[600,900]、z=110范围运动；不得先越界再回来。FINAL_NORMAL从Inner出发，FINAL_EMERGENCY从声明的当前环出发，二者均在当前环以内向pad推进，高度非增、半径非增、角向不逆行；直到pad上方15m。

在final末段允许水平速度降至0，这是连接垂直下降需要，不适用INBOUND/TRANSFER的2m/s下限。不得存在正时长的全速度为0的空中等待段；不得为等待资源在小范围重复绕圈。正常绕环半圈导致航向累计变化180°不属于“掉头”；逆向角运动才违反本规则。

### 7.4 固定衔接与下降剖面

到达pad上方15m时：水平速度0、垂直速度-0.5m/s、水平和垂直加速度0。正常和应急使用同一个垂降模块。

固定剖面采用`s(u)=10u³-15u⁴+6u⁵`，只有以下一个正式版本：

| 段 | 时长/s | 垂直速度 | 下降距离/m |
|---|---:|---|---:|
| 平滑增速 | 4 | `-0.5-1.0*s(t/4)` | 4 |
| 匀速下降 | 31/6 | `-1.5m/s` | 7.75 |
| 平滑减速 | 13/3 | `-1.5+1.5*s(u)` | 3.25 |

总时长13.5s，高度由速度的解析积分计算，不用每步Euler累积。速度最大1.5m/s、垂直加速度最大约0.64904m/s²、垂直jerk最大约0.46120m/s³，均满足本合同包线。起终加速度为0，接地速度为0；段间C2连续。不得自行缩短减速段或以停止在空中等待代替剖面。

接地事件发生在z=0、v=0，服务开始；不得以最大下降率穿地再清零。此剖面是DESIGN，不是厂商着陆程序。低空地效不用于免费节能，且不声称模拟接触动力学。

### 7.5 轨迹构造与返回值

实现可用解析极坐标过渡、分段多项式或样条，但必须满足上述对象和验证条件。生成器返回FEASIBLE、PROVEN_INFEASIBLE、NOT_FOUND或INVALID_INPUT；不允许将预算不足写为不可达。

用于轨迹单元测试的初始持续时间样本固定为20、25、…、180s；这只是测试样本，不是物理时长上下界，也不是未来调度算法的候选预算。资格检查对已知可行轨迹必须加密或直接构造，不能因粗网格失败就修改场景几何。

## 8. 六pad服务与资源预约

正常final启动前必须保证目标pad及相关进近空间在需要时可用。允许当前忙、未来确定释放的pad；不能在上方等。pad的占用从进入其独占下降资源时段开始，延续到真实接地＋服务结束。其他final对同pad的靠近仍通过实际轨迹与在pad服务的实体检查。

服务从接地计时，60/120/240s不可抢占，包含地面清空。对已经开始下降、final或SERVICE的飞机，应急不能删除、赶走或加速其服务。所有在pad的飞机在CLEARED前保留参考位置，参与与空中实体的80m几何检查。

应急的pad可用条件比正常未来预约更明确：**应急启动时该pad必须当前没有SERVICE/垂降占用，且没有不可撤销的已开始final依赖；可撤销的未开始普通预约可以被应急重排。**一旦应急获批，该pad从启动到应急接地＋服务结束被独占预留，不能再插入普通着陆。其他pad无需全局停用。

若当前所有pad忙，应急飞机继续在所属槽位盘旋并等待下一次可用性事件，不先离环到中心等待。可以预测未来释放以判断风险，但不能假装此刻空闲。

## 9. 正式能源代理模型与SOC

### 9.1 真实性等级与唯一实现

正式使用`eh216s_lit_proxy_v1_0`：Pradeep与Wei（2019）的共轴动量理论结构＋Pradeep等（2022）的profile功率形式＋本合同明示的三维和电池近似。[S5、S6]

**该模型是可执行的研究替代模型，不是完整实机标定。**不声称能重现EH216-S全部航时、温度、电压塌陷或老化。不会因为后续找不到实测曲线而临时换成固定每秒扣电。全部公式、数值和移植来源在附录A；配套纯Python参考程序用于独立数值对照。

这里对“尽可能接近真实”的具体边界是：保留受力、速度、转弯、下降、功率限制与统一电量记账；不伪造不存在的机型实测数据。未来实测校准必须另立版本，不能只修改系数却继续混用本版结果。

### 9.2 SOC与电量

```text
Q = 252Ah
V_eq = 85V                     # DESIGN恒压近似，不是官方平均电压
I(t) = P_batt(t)/85
SOC_dot = -I(t)/(3600*252)
E_J = integral(P_batt dt)
E_eq_full = 21.42kWh           # 由恒压近似推导，不称为官方可用能量
```

初始化SOC是该代理模型的剩余电量比例。电池端与轴功率分开；推进效率固定0.90（DESIGN）。不模拟电压塌陷、温度、SOH和单电池不均衡；不再保留等待选择的电压模型字段。

### 9.3 能源与动力学的联合约束

新增机动必须有正的接地/端点前能量，功率不得越界。每电机最大连续参考5.8kW、最大功率18kW；电池电流参考≤2016A。研究中均匀分摊推力和功率。

每次终端区访问中，累计轴功率超过16×5.8kW的时间不得超过120s；不在两个轨迹之间清零。入界累计峰值时间初值为0，表示终端区开始时峰值预算完整可用的边界假设，不推断上游真实热状态。这是对2min最大功率数据的**保守累计预算实现**，不是厂商已经公布的热恢复模型。超预算候选拒绝；实际执行触发则记动力/能源失败。

地面服务期间不扣航空推进能耗，不模拟充电；接地SOC冻结用于落地指标。机载辅助/空调负载本版本不建模，不能声称其真实功耗为0。

### 9.4 下降与模型域

下降不得通过负功率或再生充电增加SOC。动力学可行而功率模型域外的轨迹仍不可提交。按附录A检查轴向下降比`V_n/v_h_effective ≥ -0.28`及正常工作根；不通过则返回ENERGY_MODEL_DOMAIN，不进行零截断掩盖。

## 10. 25%落地储备的检查时点

本版参考CAAC TCDS TC0078A、Rev.0（2023-10-12）中“**落地时最低电量不得小于25%**”的电量限制。[S1]

**合同检查点固定为完成垂直下降并接地的瞬间，即进入LANDED_SERVICE之前。不是离开Inner时，不是到达15m时，也不是服务结束时。**正常final批准条件为：

`predicted_SOC_at_touchdown ≥ 0.25`。

因此在降落程序开始前，要从当前SOC中扣除完整final和13.5s垂降的预测电量后再检查。仅检查启动时SOC≥0.25不合格。到达15m时SOC恰为0.25且后面还要耗电，不能作为正常降落批准依据。

原数据单未提供全部飞行手册细节，本版不杜撰自动降落触发点或关机后耗电要求；其接地检查语义已经固定，不把这种资料边界变成实现者可任选的解释。首次接地到服务结束的地面用电不属于该落地储备指标。

应急允许接地SOC低于0.25，但仍需有足够可用能量完成所有空中段；另记`landing_below_reserve`。删除10%特殊门槛；不将0.25解释成电池物理耗尽点。

## 11. 应急直达、提前触发和失败语义

### 11.1 直接从任意环到pad

应急允许以下边：`Outer→pad`、`Middle→pad`、`Inner→pad`，但不在Middle/Inner槽位中间落座。轨迹从当前实际状态平滑脱离，向内穿越环间区域，最终进入Inner以内，汇入所选pad上方15m并执行同一垂降剖面。

“内部空域”不意味着外环飞机瞬间位于所有环内部。Outer出发必须经过Middle、Inner半径所覆盖的区域；经过时与稳定飞机、所有转移、正常final和其他应急轨迹连续检查80m。没有隐形的安全应急走廊，没有应急专用pad，没有全空域清空。

### 11.2 应急资格和提前触发

应急不是普通调度器随时可调用的低成本捷径。每架飞机维护不可由任务标签伪造的`emergency_eligible`和不可逆的`emergency_declared`。

正式触发规则：在每个执行步/精确事件，从当前稳定槽位，或当前已承诺机动结束的预测槽位，计算**无其他交通**条件下到六个pad的可执行应急候选，取其中最小电量`q_E`。这只是尽早告警的几何/能源参考，不是可立即着陆证明。

```text
trigger = (SOC_at_decision_state <= 0.35)
       OR (SOC_at_decision_state - q_E - q_hold_10s <= 0.25)
```

其中`q_hold_10s`由所属环10s真实功率积分计算。0.35和10s是固定研究告警参数，不是厂商应急触发值。参考候选NOT_FOUND时，不把q_E设成0：触发`rescue_reference_missing`风险告警并使用已通过的对应几何模板补充查找；在资格测试中此类缺失必须修复。

0.2s监测只更新解析状态、已缓存参考机动能量及触发条件，禁止每个执行步运行一次全机群搜索。参考轨迹可按当前相位解析实例化并缓存；缓存无法提供有效候选时必须补算并计时，不能用不带误差界的插值降低能量需求。

对活动机动，使用其末状态SOC进行预测；必要时提前设置`emergency_pending`，但不改变当前轨迹。结束后才取得相应环的应急资格。已有正常final继续其完整落地，不中途换pad；若预测低于储备，记录异常并按物理能源可执行性处理。

### 11.3 调用顺序与防滥用

应急资格满足时，系统必须在同一事件周期调用应急处置接口，不等下一个5s心跳。若当前Inner已经存在一个立即可启动且预计接地≥0.25的正常final，可直接正常执行并关闭本次未声明告警；否则正式声明应急。

声明后只允许保持当前位置对应槽位、继续已承诺机动或启动应急final；不再启动新的普通环间转移来规避应急计费。声明不可通过换标签消除。外部人工应急只在专门fixture中注入，正式正常来流不随机赠送应急权限。

有合法救援机会时，处置接口必须尝试提交；代价用于评价此前调度是否造成应急，不能因为外环罚分较高而故意不救。接口本身不学习，不绕过最终验证。

### 11.4 多机争抢和代价

多个应急请求必须联合验证，不能分别批准同pad或相交轨迹。未开始的普通预约可以重排，已经开始的机动和服务不可抢占。若所有待救飞机无法同时救援，接口输出获批子集及未获批原因；不得声称选择过程提供无条件零失败保证。

| 实际应急起飞环 | 单次附加代价/等价延迟秒 |
|---|---:|
| Inner | 1200 |
| Middle | 2400 |
| Outer | 3600 |

在首次应急final真实启动时收费一次，不按步重复、不在接地再收一次。记录声明环、实际启动环、声明时间和启动时间；活动转移结束后从目标环起飞则按该实际源环计费。真实轨迹能量和时间仍按统一模型另算；不得为了外环代价高而人为乘大物理耗能。

### 11.5 pad不空时不能立刻等同于最终失败

- **EMERGENCY_WAITING**：当前无法启动，但飞机仍有能量等待资源变化；继续盘旋和耗电，不去15m悬停。
- **NO_RESCUE_FOUND**：搜索/生成预算内没找到救援，保留原因；不称为数学上不可救。
- **PAD_DEADLINE_MISSED**：在固定已开始服务和机动条件下，能证明所有pad最早可用都晚于本机最后可起飞救援时刻；计应急服务失败事件并继续保留状态，禁止瞬间删除。
- **ENERGY_FAILURE**：接地前SOC到0、无法提供获批轨迹所需功率，或累计峰值预算耗尽；是物理能源失败。

最后可救时刻需包含等待、完整应急final和垂降，不是只看剩余盘旋时间；不能在240s预览结束就宣称未来没有pad机会。临时当前忙但在电量耗尽前释放的pad，应在释放后尝试救援。

### 11.6 失败处理与统计边界

本版目标是减少失败率，而不是靠准入证明排除所有未来失败。正常压力测试允许出现能源失败并正确报告；这与“实现有bug”不同。获批轨迹在确定性执行中突然功率超界，则属于执行/验证不一致的实现问题。

发生真实ENERGY_FAILURE或已执行80m硬安全违反时，精确定位时刻并停止本次物理episode，不模拟坠落动力学，不删除该机后继续把空位计作正常吞吐。其余尚未落地飞机记`CENSORED_DUE_TO_FAILURE`；尚未揭示的预生成请求记`UNRELEASED_AT_FAILURE`。

必须报告：episode失败率、已准入飞机能源失败率、应急声明后的成功/失败/未决数、pad截止失败数、首次失败时间、被中断数量。失败截断episode的平均延迟不能与完整清空episode混成无条件效率均值；综合统计必须标注其截尾。失败不能被“中止仿真”改写成成功避免事故。

## 12. 唯一80m间隔与连续验证

所有受管飞机参考中心采用三维欧氏距离，**d(t)≥80m**。80m等号满足要求；任何真实d<80m均属于违反，不存在78m容忍，也不存在82m新增计划阈值。

浮点误差只通过可验证距离区间处理：下界≥80可通过；上界<80判不安全；其余继续收紧或返回UNKNOWN。对解析恰为80m的样例允许解析证明。数值分类不得通过`80-eps`把真实低于80的轨迹批准。距离界收敛精度目标1mm，未收敛UNKNOWN拒绝。

同环槽位和不同稳定环可使用结构证明。转移/入场/final/下降之间必须检查连续时间；采用解析最小距、区间界、保守包络或带误差界折线，不得仅抽样。

每次新提交对整个批次及全部未变更交通验证。部分搜索中的放松检查不能冒充最终联合验证。对目标稳定跟踪，须检查与其他活动机动直到其结束及之后的结构间隔，不能只检查候选自身飞行结束前。

默认无自动避碰改写。BlueSky不是必需依赖；若后端或可视化平台改变权威轨迹，则验收失败。

## 13. 原子事件、执行和缓存

同一时刻顺序：推进权威轨迹和能量→定位接地/真实失败→结算机动完成及源清空→结算服务结束→揭示新请求→更新应急→形成唯一快照→执行一次触发的决策/测试动作→联合验证→原子提交。

资源区间采用`[start,end)`，几何连接时刻仍纳入检查。同一时刻服务刚结束可以释放，但实体清空事件要先完成。多请求并列由明确request_id排序或确定性联合批次处理，不由容器遍历顺序决定。

缓存关联geometry、vehicle、energy、trajectory和状态版本。改变任何有关参数后失效。稳定环功率可缓存；动态轨迹可预积分；搜索预测与执行必须引用同一能源内核。启用缓存不能改变是否有解、应急时点、结果或精确事件语义。

## 14. 数据接口和统计合同

### 14.1 最少接口

必须有：VehicleProfile、EnergyProfile、AircraftState、SlotCalendar、PadCalendar、TrajectoryPlan、只读WorldSnapshot、ArrivalManifest、EmergencyStatus、ValidationResult、EventLog及ReplayBundle。

必须支持：生成单机候选、连续运动/功率验证、联合预约/间隔验证、原子提交、按任意事件推进、应急资格更新、失败定位、独立episode审计、既有viewer的只读重放适配。**删除v0.9强制validate_joint_recovery_completion作为提交条件的接口要求。**

拒绝原因不得只返回false：需区分非法正常跳环、无应急资格、已承诺修改、资源依赖、陈旧状态、过期时间、运动越界、功率越界、模型域外、SOC不足、落地储备不足、slot/pad冲突、间隔违反、UNKNOWN及NOT_FOUND。

### 14.2 守恒关系

```text
N_planned_manifest = N_offered_until_stop + N_unreleased_after_stop
N_offered_until_stop = N_admitted + N_rerouted
N_admitted = N_physically_landed + N_failed_before_landing + N_airborne_or_censored
```

SERVICE和CLEARED都属于已物理落地，不能重复加总。应急、低于储备、任务类别是交叉属性，不再加进总数。另报截止3600s的结果、清空结束结果和失败截断结果。

### 14.3 指标与固定代价

必须保存：正常落地、应急落地、低于25%落地、能源失败、安全违反、分流、各种截尾；飞行时间、保持时间、转移/final/下降时间；实际J/kWh与SOC；pad利用率/服务时长；槽位占用/预约/在途；决策次数、各模块CPU时间、缓存命中和可视化开销。

第一阶段只固定代价分项，不把它们写成学习奖励。分流600，应急1200/2400/3600，能源失败1,000,000等价延迟秒/架。失败率始终单独优先报告，不能凭有限罚分声称硬保障。总报告代价为实际累计空中时间＋上述事件代价；电耗独立报告，不凭空设货币价格或重复纳入应急代价。

对未完整完成的episode，总报告代价是截至停止时的累计量，必须标注下界/截尾，不得据较小累计量判其更优。优化器未来如何处理这些分项不在本合同中规定。

## 15. 既有可视化平台的强制验收

### 15.1 必须复用本地平台

实施前定位仓库已有visualization入口、PyVista或其他现用renderer、telemetry适配器与启动方式，并记录实际路径。优先扩展现有平台，**不得另做一个简化动画网页来冒充原平台已接入**。若需适配新schema，只改数据适配与新增显示层，不能由viewer另算一套物理世界。

CPU服务器负责仿真和重放包；本地平台读取重放包进行交互观察。服务器不要求CUDA/GPU。无界面测试默认关闭viewer；图形帧率不控制仿真时间。无需先迁移BlueSky。

### 15.2 必须可见的内容

三环真实高度、旋转槽位ID/相位及FREE/RESERVED/OCCUPIED/DEPARTING；飞机ID、所属环、服务类、SOC、应急标志；当前已承诺轨迹、未开始软计划及其依赖；六pad的当前状态和剩余服务秒数。

可以选择任意飞机查看速度、加速度、jerk、功率、SOC时间序列。显示实际最近飞机对、最小三维距和对应时刻。80m保护球必须说明是“单机周围的排斥距离”；若用两个相交球表示成对保护，只能使用40m半径。不得画80m半径球后以球相交表示80m冲突，造成阈值翻倍。

正常与应急轨迹、拒绝候选、冲突点、分流箭头和失败位置需要明确图例。2D俯视、侧视/高度视图和3D均可切换；侧视高度放大必须标比例，距离判定始终用真实坐标。

### 15.3 交互与证据

要求暂停、逐执行步前进、按事件跳转、拖动时间轴、0.25×/1×/4×/10×回放、选机与相机跟随；可隐藏全部或只显示选中轨迹。已开始轨迹不能因拖动UI被重新生成。

日志至少保存0.2s状态、全部精确事件、权威轨迹参数与hash，允许viewer在任意时间解析插值。禁止对实际轨迹另做平滑滤波以掩盖折角。候选拒绝过程只能以标注的诊断覆盖层展示，不能显示成真的执行过。

每个目视场景需有可加载ReplayBundle、固定seed和命令、自动断言结果、至少俯视/侧视/3D截图，以及覆盖关键事件的录屏或可重复交互回放。数据包包含manifest、配置hash、代码commit、trajectory文件、states、events、metrics和判定报告。

### 15.4 人工验收不是参数二次确认

所有设定已冻结。研究负责人需要观察的是**实现是否符合合同**，不是再次选择规则。自动测试状态与人工观察状态分开保存：`automation_status`、`visualization_integration_status`、`researcher_visual_acceptance`。

未完成本地平台观察时，只能报告自动测试完成，不能报告第一阶段总PASS。负责人提出轨迹不合理、显示与数据不一致或事件解释错误时，应按对应条款修实现并重放，不能悄悄修改合同。

### A.2 受力

在无风情况下v为空速也为地速。设`v_h=||(vx,vy)||`：

```text
D_xy = -0.5*rho*2.11*v_h*(vx,vy)
D_z  = -0.5*rho*1.47*abs(vz)*vz
T_vec = m*(a + g*e_z) - D
T = ||T_vec||
V_n = dot(v,T_vec)/T
V_p = sqrt(max(0, dot(v,v)-V_n²))
```

T必须为正且推力向上分量为正。环飞的向心加速度进入a，因此转弯负载进入T；不能在加速度字段只保留切向加速度。

### A.3 诱导速度与共轴修正

```text
v_h_single² = T/(N*2*rho*A)
v_h_effective = sqrt(2)*v_h_single
V_n/v_h_effective >= -0.28
v_i * sqrt(V_p² + (V_n+v_i)²) = v_h_single²
```

取`v_i≥max(0,-V_n)`且`V_n+v_i≥0`的正功率工作支。必须括住根并收敛；无对应根或域外即拒绝。参考程序二分80次，残差相对`max(1,v_h_single²)`≤1e-8。

`P_induced=(1+chi)*T*v_i=2*T*v_i`。采用这一共轴约定后，**不能再将N的盘面积减半再乘一次同类修正**，否则重复计入。

### A.4 功率

```text
P_translational = dot(T_vec,v)
P_profile = N * rho/8 * sigma * Cd0 * A * U_tip³ * Fp
P_shaft = P_induced + P_translational + P_profile
P_battery = P_shaft/eta
I = P_battery/V_eq
SOC_dot = -I/(3600*Q)
```

`dot(T_vec,v)`已包括势能变化、加速度机械功和克服阻力做功，不再另加m*a·v或m*g*vz。P_profile在本版为固定近似，不假装模拟实际RPM控制。应检查正功率和模型有效域，不将负值截0后通过。动力学最优轨迹不属于这个功率函数。

本版不模拟电压塌陷，因此SOC>0不代表真实电池一定能供同样电流；这是公开数据不足下明确的模型限制。动力失效仅按代理模型能量、参考电流/功率及累计预算判定，不宣称覆盖全部实机故障。

### A.5 数值参考与累计积分

配套`energy_reference_v1_0.py`仅使用Python标准库，输出的自检JSON是公式级检查，不是本地仓库测试报告。固定检查点的电池功率为：

| 状态 | 电池功率/kW，约值 |
|---|---:|
| 纯悬停公式检查（禁止用于等待） | 124.95960 |
| Outer稳定盘旋 | 68.07801 |
| Middle稳定盘旋 | 74.81287 |
| Inner稳定盘旋 | 92.77313 |
| 匀速垂降1.5m/s | 125.32443 |

这些值是代理模型计算结果，不是EH216-S遥测。不得因为某个速度更慢却更耗电，就人为改成距离线性模型；诱导功率随速度变化是该模型的一部分。也不得据此宣称已经验证了真实机型的最佳经济速度。
