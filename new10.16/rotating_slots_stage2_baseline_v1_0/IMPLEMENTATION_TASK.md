# Stage2实施入口

先完整阅读`rotating_slots_stage2_baseline_contract_v1_0.md`及配套YAML。本文件是开发任务入口，不覆盖主合同。

## 本轮只做这些

1. 审计实际HEAD、现行规则和工作区，按FT-RS-S2-1.0建立新实验策略层。不要覆写旧Stage1结果。
2. 能源任务失败改为：单机记失败并罚一次、隔离和原子清理资源、其他交通继续。真实间隔违反和程序错误仍停止无效运行。记录失败后抽象的局限。
3. 拆出只读PlanningSnapshot、公共CandidateProvider/EvaluationContext，不能通过真实`submit()`试搜索分支；统一处理阈值精化。
4. 只实现Energy-slack与真正多步Rolling-Horizon CP-SAT。共用准入、应急、数值后端和候选策略。不要添加FCFS、beam、单步研究组、oracle或任何学习训练。
5. 预测H=240秒、最多正常3阶段，每机最多8条移动预测链＋KEEP/WAIT；实际只提交下一机动，不能依赖未承诺未来离开放行当前动作。
6. 记录每次正常调度与完整公共dispatch的wall/CPU；候选、验证、提交和fallback不能藏到计时外。不要把仿真总wall当算法响应时间。
7. 首轮从36架空中＋3架地面服务的固定繁忙初态开始，两方法读取同一180架/小时、seed71、3600秒manifest。先报告同一运行的60秒，再接续，不重新跑一遍。
8. 自动campaign上限10小时，9.5小时停止计算并归档。先完成共同窗口，未达3600秒诚实标预算截尾；不继续反复寻优，不用额外种子制造好结果。
9. 跑28项短的针对性检查，复用既有PyVista回放和独立安全检查；不要建立另一个复杂验收平台。未运行、未人工观察必须明确标记。
10. 最后给出质量、逐次调度耗时、成本分解、候选截断、CP状态、fallback和剩余瓶颈。CP不必胜出，实时目标不必被伪造为达标。

## 必须特别避免

- 因失败继续统计就允许无电飞行、免费落地、补生飞机或隐去失败。
- 直接取消其他飞机已经开始的机动，或把未提交的多步预测自动执行。
- CP-SAT只做下一动作，却称为多步MPC。
- 将有限候选NOT_FOUND、UNKNOWN、超时写成全局物理不可行。
- 忽略末端飞机、上游等待、服务中的地面实体或未来pad保护区间。
- 只比较CP solve时间与未来学习推理时间；只比较幸存成功样本。
- 承诺当前速度下一定在10小时内跑完一小时的两算法实验。

完成每个实施阶段后更新实际实现说明和结果状态；发现错误修错误，不以参数放宽或更换场景代替修复。
