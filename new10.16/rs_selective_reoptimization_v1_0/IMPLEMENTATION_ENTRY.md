# 实施入口：Stage3-R 选择性重优化

合同编号：FT-RS-SELECTIVE-1.0。当前包是规范，不含已经改好的仓库算法。

## 首先执行

1. 阅读主合同第0—6节并核对实际分支，绑定配置、目标、应急和延迟版本。
2. 保留旧OFF/full路径、旧结果及checkpoint；新建独立研究分支。
3. 加入scope和背景接口，不删除snapshot飞机；局部检查、全局目标和真实提交一起修改。
4. 先运行A01—A20与X01/X02，之后仅进行A规定的小对照。
5. 输出A报告，经人工审查后再决定进入B；不得一条命令自动跑A/B/C。

## 三阶段

- A：K8、上限12、规则选择；关旧候选rank；相同20秒接入协议。
- B：同一集合工厂最多6组；一次编码选一组；新数据新模型，不能加载旧rank权重。
- C1：K4/8/12与时间约束；先补多K证据。C2：单独、条件性比较20/10秒接入。

阶段预算A/B/C/归档分别2/5/2.5/0.5小时；不足即报告，禁止重置或为获胜反复重跑。源代码编写和人工阅读不计入自动计算；科学采集、标签、训练、失败执行均计入。

## 包自检

在本包目录可运行：

```sh
python validate_package.py
```

它仅检查文档、配置、Schema、测试目录、示例与哈希的一致性，不运行物理仿真、CP或模型，不替代32项实现验收。新增仓库入口命令应由实施者完成并在docs登记，本包不假装这些命令已经存在。

## 主要易错点

`EvaluationContext.decisions`必须同步改为S；`JointDownstream`仍含所有需求；未提交suffix不是承诺；选中飞机不必全部行动；局部空间失败不是全局无解；scope扩展和fallback不重置预算；预测与实际执行时刻不能混用。

## 每阶段交付

源码差异与运行绑定、相关测试结果、原始运行/选择日志、共同时间边界结果表、权威回放、人工观察状态、已知限制与下一步结论。统计负结果可以结束阶段，不能写成无损加速。
