**合同编号：FT-RS-SELECTIVE-1.0**  
**简称：Stage3-R / RS-SELECT**  
**版本：1.0；日期：2026-10-27**  
**状态：研究实现规范已编写；尚未实施、训练或完成实验验收。**

> 核心变更：从“为全部正常可规划飞机搜索候选，学习只调整候选次序”，转为“全局状态持续可见，每轮只开放一组飞机的决策变量；学习选择该组，传统CP负责组内联合优化，确定性模块负责全部执行约束”。

## 1. 为什么改变学习对象

最近高流量300秒实验，H/L正常着陆为14/15，正常规划累计工作约189.54/196.21秒，dispatch约208.65/227.68秒。L的候选尝试从829减为707，CP时间从24.98秒减为17.85秒，但轨迹和前缀验证增加，特征与推理累计约22.80秒。此结果未建立整体加速，也未建立稳定质量优势。[R1]

现有 `CandidateProvider.iter_progressive_columns()`仍为全部正常决策飞机建立候选生成器，`EvaluationContext`仍以全部正常决策飞机为联合检查集合。旧学习层介入的是单机候选构造内部，不直接缩小这层集合。[R2]

本次检验三个独立假设：

- **H-A：结构缩减有用。**只优化少量有关联飞机，能否减少真实端到端计算，而不靠删除背景约束或丢失需求获得表面收益？
- **H-B：选组值得学习。**在同一局部框架、相同K与预算下，学习是否比透明规则更好地选择联合重规划对象？
- **H-C：规模应适应状态。**资源耦合、能源压力、可用时间变化时，选择不同K是否改善质量—计算权衡？较短接入提前量能否进一步带来实际服务收益？

不预设三个假设均成立。若A不成立，停止进入B，查公共后端；若A成立而B不成立，可以保留高效传统局部方法；若B成立但C无增益，保留固定K学习方法。不得把“阶段完成”定义成必须获胜。

## 2. 文献与公开实现的具体借鉴

### 2.1 MAPF-ML-LNS：选飞机组，而非逐项候选评分

Huang等（AAAI 2022）从若干候选agent子集中学习选择待重规划的集合，保留其他路径。论文第4节及公开 `LNS.cpp` 展示了子集提出、特征评分和对子集重规划的组织方式；公开实现测试路径使用邻域特征的线性评分。借鉴到本项目：**便宜地提出少量集合，批量打分，只物化被选集合的轨迹**。不复制其网格路径、SIPP/PP或sum-of-costs目标，也不宣称复现其论文收益。[P1, C1]

### 2.2 Neural LNS for MIP：固定其余变量，再调用成熟求解器

Sonnerat等的图1与第3节把选择变量与子问题求解分开：只解除一部分赋值，其他变量固定，传统solver求子问题。借鉴到本项目：显式 `replan_ids` 和固定背景，而不是把未选飞机从snapshot删掉。其可行初始赋值及离线专家假设不能直接套用：本项目存在持续到达、有限电池与非承诺预测后缀，不能保证“所有飞机最终落地”的全局可行计划一直存在。[P2]

### 2.3 BALANCE：规模也是选择变量

Phan等（AAAI 2024）使用两层bandit选择destroy启发式和邻域大小。已核对 `BasicLNS.cpp` 中策略/规模采样与统计更新，以及 `LNS.cpp` 的局部替换流程。借鉴“规模选择与组选择分开、按真实效果调整”，但本版C先采用带成本约束的规模选择，不直接移植其标量奖励或Thompson公式。公开代码与本文的新设计不得混称。[P3, C2]

### 2.4 ADDRESS：关键种子及其阻塞关系

Phan等（AAAI 2025）将延误较大的agent作为种子候选，再构造相关邻域，避免不断盲目探索。本项目借鉴关键种子、历史无进展记录和相关对象扩展；把“延误”扩展成能源、机会、审查年龄及资源阻塞。这里只据论文核对方法，未运行ADDRESS项目，不声称完成代码复现。[P4]

### 2.5 与本研究已有材料的关系

已有研究原则是安全/能源可行性与调度学习分层；本合同改变的是搜索对象，不是物理控制层。[U1, U2] 文献LNS通常在一个静态可行完整解上反复改进。本方法首先是**在线受承诺约束的选择性重优化**；只有在同一快照、同一完整预测基准上做局部替换时，才具有LNS式邻域含义。不能借用静态LNS的单调改进来宣称闭环吞吐或最终能源失败必然不劣。

## 3. 冻结内容与非目标

继承实际绑定配置中的三环、共同角速度、槽位、四入口、六pad、服务分布、80m连续间隔、正常落地储备、运动/功率/能量约束及数值策略。保持正常只向相邻内环转移、无同环换座、无跳环/向外机动等规则；应急按现有共同机制执行。

本次不得：

- 通过移除背景飞机、缩短认证范围、降低安全距离或忽略峰值功率提速。
- 修改服务时长、流量、SOC、应急触发以制造学习优势。
- 把选择组中的所有飞机都强制移动；CP可以让其中部分保持。
- 先为所有飞机生成完整候选，再用模型筛飞机。
- 把旧候选排序模型或标签直接改名成为子集选择模型。
- 同时叠加旧高频学习候选排序、在线RL、世界模型和学习安全判定。
- 为新选择器新增专用“让座”物理动作。阻塞飞机只可执行原有合法向内动作。
- 宣称本合同解决真实硬件定位/跟踪误差或提供航空安全认证。

保留旧H/L运行入口及历史结果。新算法族采用独立ID：`FULL_H`、`RULE_LOCAL_K8`、`LEARNED_LOCAL_K8`、`RULE_LOCAL_ADAPTIVE`、`LEARNED_LOCAL_ADAPTIVE`。旧L只作历史对照，不是A/B默认运行组。

## 4. 三种集合与两种计划：最重要的语义

设当前已揭示全局状态为x，未来接入点为t_e。

- **V：全局可见对象。**所有已准入飞机、地面服务飞机、已到达上游请求及真实预约。
- **U：正常可重规划飞机。**沿用当前 `_decision_aircraft()` 的资格规则，并明确其首个可调整时刻。已经交由共同应急处置者不由选择器重新抢回。
- **S：本次开放决策的飞机。**`S ⊆ U`；只有S生成新候选并成为可选择的机动变量。
- **B：固定背景。**`V_aircraft \ S`；完整保留实际轨迹、资源、能源和下游需求。

区分两种计划：

1. `committed_continuation`：真实已批准active/soft机动与既有续飞规则，是执行和认证事实。
2. `predictive_suffix`：尚未授权的后续计划，仅用于评分和候选复用，不能作为背景飞机将来一定释放槽位的依据。

**未选不等于消失；未选也不等于无限安全保持。**背景飞机持续运动、耗电、占位、参加安全检查，必要时进入共同应急。holding的无限几何尾迹仅用于既有冲突预测，不是无限能源保证。

局部计划不得改变任何未选飞机的真实预约、轨迹或依赖。若某个候选需要B中的飞机主动改变尚未承诺的行为，这个候选暂不能批准；可以在剩余预算内将该飞机纳入S并重新联合求解，或放弃该候选。

## 5. 局部优化问题与全局目标

### 5.1 决策空间

对i∈S，构造有限多步候选集合C_i，包含FOLLOW/KEEP、WAIT及原有合法正常链；外环最多预测O→M→I→pad，实际仍只授权可在接入点开始的首机动。

对j∉S，使用固定续飞描述b_j，不生成新轨迹替代。求解：

\[
\min_{c_i\in C_i,\ i\in S}\ \widehat J_x(\{c_i\}_{i\in S},\{b_j\}_{j\notin S}).
\]

CP只开放S的候选选择变量。可执行性覆盖S内部、S对B、资源和释放依赖。B对B的既有证书仅在真实输入和覆盖时间仍相同时复用；无证书不能跳过。

### 5.2 目标不随S偷偷变化

主线上线目标继承 `downstream_service_v8`：`(F, -L, risk, Ehat, tau)`及其实际单位、量化与缺失语义。实际实验继续独立统计正常、应急、能源失败、未完成、分流、能耗与等待。预测risk不等于真实应急数，预测F不等于已发生失败。

建立 `GlobalEvaluationFrame`：在选择S之前，为所有已知需求构造共同基准与固定虚拟pad分配/队列顺序。同一快照的不同S必须使用同一框架。选中候选替换其自身需求后，全局评价仍包含B的后续等待和能源影响。

此处新增 `global_preselection_frozen_v1` 评价输入政策：虚拟队列基准在选择前固定，不得对某组使用刚算出的全量参考、对另一组使用未知代理。它保留v8目标公式，但可能改变历史实现的评价输入时点，必须独立版本化。A/B/C的FULL_H正式对照也使用同一公共frame接口（以S=U调用）；历史归档H只作背景。OFF模式仍保留旧完整实现，不把两者称作逐位等价。

当前 `JointDownstream.fixed_demands` 可作为扩展起点，但必须检查：

- 不因S改变就删除背景需求或重新安排全体虚拟队列的初始身份。
- 不把背景等待当常数：选中机动占用pad会改变背景飞机的预计等待。
- 真实预约与背景/候选的pad区间按身份去重，避免双重占用。
- 已在最终进近、垂降、地面服务的对象按实际状态记账，不能被重新当作从环出发的需求。
- UNKNOWN参考使用现有显式代理与mask，不凭空变成已知可行。

因此CP中可能仍有与全部需求有关的辅助排队变量；**只承诺减少可替换轨迹组合，不承诺整个模型所有变量只剩K个。**必须分开报告决策变量、辅助变量和约束规模。

### 5.3 可行基准与局部改进的边界

每个局部问题保留当前合法续飞选项，避免一开始破坏已有承诺。它不意味着全局任务一定能完成：有限能源或过载可能使继续等待不是可持续完成策略。

只在同一快照、同一评价框架和证书范围内维护best-so-far。后续方案不能以更差的目标替换已认证incumbent；但未承诺的长后缀和实际执行前缀必须分别检查。局部候选不足记为`LOCAL_SEARCH_INCOMPLETE`，不能记为全局不可行。

## 6. 统一接口与文件级实施位置

建议新增 `terminal_marl/core/rotating_slots/selective_replanning/`，避免把选择逻辑继续塞进单个大文件：

| 文件/接口 | 职责 |
|---|---|
| `scope.py` | `PlanningScope`、资格、固定背景、集合一致性 |

| `relations.py` | 廉价的资源和机会图，不承担安全证明 |
| `selectors.py` | Rule选择器、候选集合工厂及模型适配 |
| `local_problem.py` | S候选＋B固定续飞，局部求解和统一评价 |
| `model.py` / `dataset.py` | 阶段B独立模型、数据与新标签 |
| `size_control.py` | 阶段C规模可用性、成本与选择 |
| `telemetry.py` | 子集、耗时、授权结果与可视化数据 |

必须修改现有接口，而不是删除snapshot成员：

```python
PlanningScope(
    snapshot_id, effective_time,
    eligible_ids, replan_ids, fixed_background_ids,
    mandatory_ids, nominal_k, actual_k, max_k,
    selection_reasons, relation_digest, objective_frame_id
)

CandidateProvider.iter_progressive_columns(snapshot, budget, context, *, scope=None)
EvaluationContext(snapshot, ..., *, scope=None, global_frame=None)
LocalPlanner.plan(snapshot, scope, global_frame, shared_budget)
```

`scope=None`保留旧全量路径。显式scope下：

- `EvaluationContext.decisions == set(scope.replan_ids)`，不再来自全部U。
- `CandidateCatalog.columns.keys() == replan_ids`；背景使用另一个清晰字段，不用多组KEEP伪装成开放变量。
- `_check_single()`必须检查选中候选对所有适用背景；`check_batch_conflicts()`检查S内部。
- `prefix()`只产生S的可执行新前缀；真实验证端仍读完整世界。
- `JointDownstream`使用共同frame及固定需求；全局计数不能减掉B。
- `_node()`、已有运动耗能与资源保护时间按真实依赖复用，不因为未选就重建另一套物理模型。
- CP continuation的身份包含scope、背景证书、全局frame和候选内容。改变S或背景后不把旧cut直接套给不对应的变量。
- 同一目录继续改善时复用已认证incumbent与有效cut；不宣称复用CP内部搜索树。
- `CandidateProvider.previous`必须按S合并更新，不得用本轮局部结果覆盖全部飞机的非承诺预测缓存。未选缓存可保留但须在再使用时检查绝对时间、源状态、能源与依赖，不能变成执行保证。
- 扩展S时，旧incumbent先给新加入对象补固定续飞，再在同一frame中重新评价/认证；不能因为其原证书属于较小S就直接认为新组合通过。
- scope筛选必须覆盖progressive和其他候选入口及所有冷reference调用，不能只修改主循环而留下旁路为全体飞机生成完整链。

## 7. 廉价关系图、紧迫性与公平性

### 7.1 图描述什么

节点包括全局飞机、移动槽位和pad资源。边至少区分：

- 已承诺的释放/占用依赖；
- 已知目标槽位被谁占用、何时释放；
- 即将释放的pad及潜在接续飞机；
- 同一资源/时间段竞争；
- 最近同版本检查发现的明确阻塞关系；
- 可选的解析相位/时空粗筛关系。

当前距离近不是唯一建边条件。共享未来pad的远距离飞机仍有关联。图允许遗漏不影响安全，因为最终检查完整；但遗漏可能降低调度质量，须记录。用于选组的近似边不能当安全证明，UNKNOWN不能生成“确定阻塞”标签。

禁止为建图先对所有飞机运行完整单机到pad参考或两两连续碰撞认证。读取现有缓存、真实日历、解析环位置及既有事件即可；缺失信息以mask进入选择。

### 7.2 两个年龄

- `review_age`：距该机最近一次真正完成候选/保持方案评估的时间。仅入选或预算耗尽前被遍历不重置。
- `progress_age`：距该机最近一次实际启动合法向内/着陆机动的时间。只有真正执行事件重置，网络高分、预测落地、提议未提交都不重置。

初始值从原始请求/入场和已有事件恢复；无法恢复的历史保留unknown，不编造时间。review年龄只在模拟时间中的评估结果交付后、且该机状态依赖仍适用时更新，不能在主机函数返回时提前重置，更不能把未来接入时刻伪装成已发生审查。两类年龄进入checkpoint和结果。

### 7.3 共同必须审查集合M

M是计算资源保护集合，不是新的应急规则，也不是强制动作集合。每次所有选择器共用：

1. 尚属正常规划资格，但现有能源/峰值余量估计已表明下一次计划机会前可能失去正常机会者；估计来源、适用状态与未知标记必须保留。
2. `review_age >= 60s` 的正常可调整飞机。
3. 上一次局部验证明确发现的、仍有效且必须联合修改才能解除阻塞的正常对象；已承诺动作不可被解除。

60秒是首版公平性开发值。`progress_age >= 120s`提升种子优先级，但不把全部长期等待者无条件硬塞入同一组。能源估计未知时不得宣称可安全推迟；优先安排补审，公共监测继续负责真实处置。

当|M|大于K时先提高实际选择数，最多12架。若|M|>12，报告`MANDATORY_OVERFLOW`，不得删除紧迫对象来掩盖。此时保留原执行与共同应急，允许共享剩余额度内一次明确标记的全量降级调用；该调用不得重置时钟、增加预算或宣称属于局部加速。无法完成则记录未服务对象和原因，不伪造物理无解。

## 8. 阶段A：规则子集＋局部CP

### 8.1 首版规模

默认名义K=8；实际S计入所有入选对象及有界阻塞扩展，上限12。局部搜索最多一次必要扩展、最多两次局部求解调用，所有工作共享原时钟和总额度。没有必要关系时不自动扩至12。

### 8.2 透明规则选择器

构造同一个候选集合工厂，A只采用工厂的主规则组，B再学习选择工厂中的某组：

1. 插入M，保留其优先级及理由。
2. 在剩余名额内，用四条确定性队列轮流取种子：能源余量紧迫、下游机会即将可用、progress_age较大、review_age较大。各队列内部使用已知量、unknown标记、原请求时间和稳定ID打破平局；不能让ID进入学习特征。
3. 每加入一个种子，优先补入一名有明确资源阻塞关系且可以合法向内移动的相关飞机。不是让该飞机执行特殊让座动作。
4. 达到K后停止；仅对必要的明确阻塞，允许一个有界扩展到最多12。普通同pad竞争不触发全图传递闭包。
5. 所有飞机均无需新动作的情况仍可返回等待；不能为满足“非空”而强制切环。若连续无前缀，必须输出候选/资源/期限原因。

关系缺失不自动填成安全。固定背景真实占用导致方案不可行时，可放弃候选或扩展相关对象；不能假设它以后会自发离开。

### 8.3 A的优化范围

只缩小开放对象；每机原有候选类型、多步时域、合法动作和确定性构造保留。旧候选排序器关闭。背景及正常尾部需求完整保留。阶段A不优化模型、不改接入提前量。

### 8.4 A的验证

**A0 接口回归：**新功能OFF时恢复旧逻辑。使用固定工作量/确定性mock时检查输出一致；wall预算模式允许搜索因额外测量产生细微路径差，不能宣称bitwise回归。

**A1 手工情形：**未选飞机位于候选未来交叉位置；高SOC阻塞机必须与低SOC机一起移动；实际动作数不超过可执行入选对象数；已开始机动不能修改；S为空/等于U；紧迫集合溢出；未选背景未来释放槽位；同一pad长期占用；unknown参考；审查年龄不被假重置。

**A2 同状态局部等价：**给定相同候选，将全量小模型中的非S变量固定为FOLLOW，与新局部模型比较认证结论与全局目标。至少覆盖2、4、6架的小例。此测试不是全局oracle实验组。

**A3 计算验证：**从中等/高流量开发轨迹各取4个预先登记的状态，FULL_H与RULE_LOCAL_K8各算一次。记录开放对象、候选、真实验证配对和完整工作。确认不再为B生成候选，也未先全算再筛。

**A4 闭环：**中等和高流量各300秒，FULL_H与RULE_LOCAL_K8各一次；同输入同接入协议。不能直接把历史不同日志/源码计时当作这次FULL_H正式对照。复用既有可视化，展示S/B、选中理由、真实动作与未完成飞机年龄。

### 8.5 A的退出与进入B条件

安全/记账/依赖测试必须通过；所有被拒绝计划不得执行。性能是研究结果，不设必须2倍、5倍等任意门槛。

只有在同状态和短闭环中观察到实际计算缩减，并且未发现由背景删除、能源漏计、饥饿或截止协议造成的重大退化时，才批准B。结果出现明显质量—时间权衡应标记`A_TRADEOFF_REVIEW`；没有缩减则`A_NO_STRUCTURAL_GAIN`，先做一次瓶颈解释，不立即训练。

A结束必须回答：少算的成本在哪里、剩余公共成本多大、是否只是少做动作。不得因为候选数下降就自动通过效益门。

## 9. 阶段B：一次编码，学习选择一组飞机

### 9.1 首轮不直接学习任意2^N子集

默认采用MAPF-ML-LNS式的**候选集合选择**：由共享工厂提出最多6组，模型批量评价一次，选择一组进入局部后端。每组名义K=8，M和闭包规则与A完全相同。

六类提出器：A的混合主规则组、能源种子组、pad机会种子组、阻塞链种子组、长时间无进展组、带固定种子的有限探索组。所有集合均从当前可见状态产生；去重后少于6组就保留实际数量，不为凑数重复。M过大时所有组使用相同overflow规则。

这仍是学习“选哪些飞机”：输出的是成员集合，不是某条轨迹。它限制了初版行动空间，便于产生可核验标签。任意mask生成、逐节点自回归选择和在线RL不列入B的必做范围。

### 9.2 模型与高维信息

新建独立模型ID，旧候选rank权重不得加载。首版CPU小型关系/集合编码器：

- 飞机、槽位、pad分别64维编码；两层消息聚合，或等价轻量集合关系实现。
- 全局实体编码每个任务只做一次；最多6个组使用成员mask和池化共享表示。
- 组表示包含组内/组外汇总、边界阻塞关系、M覆盖、K、当前真实计算期限；只池化S而忽略组外关系不合格。
- 输出组质量排序分数和完整局部求解成本预测；总参数不超过250,000。
- 每个任务正常一次batch forward；fallback及强制扩展不重复调用旧逐候选排序。非法输入/模型不兼容时在同一剩余额度内回到A主规则组。

特征包含SOC及mask、现有能源/峰值余量估计、环和sin/cos相位、当前承诺及最早可修改时刻、任务时长、review/progress age、真实资源释放及拥堵、已知拒绝关系。统计输入覆盖全局但不得含未来manifest、离线求解结果、方法标签或真实未来失败。

网络“关注”未选对象用于理解全局不等于为它建立决策变量。模型给全体打分但后端仍全量生成候选，是未完成本合同。

### 9.3 新标签，不继承旧候选正负对

对一个固定的可见快照、固定未来接入时刻、共同frame与额度：提出同样最多6组；离线分别运行局部后端，保留全部结果、状态、成本和置信边界。

标签记录至少包括：集合成员及实际K、必选/扩展原因、第一份认证非空前缀出现时间、最好预测全局目标、返回时间、原始求解状态、验证状态、scope overflow、是否存在可执行前缀、成本和截尾。

- 只比较同一状态/背景/未来时刻/额度下的集合。
- 未尝试、UNKNOWN、超时无结论不是物理不可行；不能编造负类。
- 有限预算的结果只称“观察到的有界参考”，不能称全局最优教师。
- 目标先按现有词典序比较；相同预测质量且成本差超出固定数值噪声容差时，才生成成本破同分偏好。不得让省毫秒直接压过失败/着陆质量差。
- 允许多组近似同优；不把唯一选中的集合标1、其他全部标0。
- 无前缀可以是合理WAIT；不当作安全失败。此类状态保留独立标签，若全组均无有效动作，不生成伪造的“最佳有效组”排序对。
- offline认证不是运行期间最终授权；真实接入和迟到结果作为另一个字段，不由静态标签冒充。

模型优化首版使用组内pairwise排序损失，加0.1权重的masked log1p秒成本Huber损失；未知成本不参与成本损失。学习率3e-4、AdamW、最多30 epoch、验证patience 5、固定种子20261027、一次正式fit。此为开发默认，不继承旧模型参数或标签。

### 9.4 数据与充分性

新采集以合法中段状态为主，覆盖中等/高流量、不同SOC、真实承诺及pad拥堵。按完整scenario祖先划分，不将同一根的相邻checkpoint分到训练与测试。

目标为8个训练根、2个验证根、2个新测试根。训练/验证每根取60/150/240秒三个可见状态，形成24/6个状态，最多6组/状态。测试根不做标签选择或调参。既有s3r23/s3r24保留为已见开发回归，不称未见测试。

这只是首版预算内目标，不保证足以学习。检查独立根数、有效状态数、可比较集合对和主要差异层级；若训练信号只来自极少状态或只有能源层，报告`B_SIGNAL_LIMITED`，不能宣称学会吞吐/可靠性。无足够有效偏好时停止训练，输出`B_DATA_INSUFFICIENT`，不通过复制样本或将UNKNOWN变负类凑数。

### 9.5 B的验证与退出

先做集合排列不变性、mask、全局资源对应、训练/验证隔离、future-state/lead绑定、一次编码计数、fallback同预算测试。

离线报告同快照组选择的预测目标regret（仅针对有界参考）、deadline内非空认证率、成本误差、模型额外工作。主验证为RULE_LOCAL_K8与LEARNED_LOCAL_K8在两类300秒场景同协议配对，各一次；阶段A完整参考保留。正式泛化结论需要后续额外独立种子，首轮只作试验性证据。

只有在同局部框架下观察到质量—完整成本的有意义改善，才能称为学习收益。若仅相对FULL_H改善、相对RULE_LOCAL无增益，结论是结构分解有效而学习增益未成立。允许保留规则方法，不反复fit到赢。

## 10. 阶段C：动态K与更短接入，必须分两步

### 10.1 C1：固定20秒提前量，先只改变K

规模选项为{4,8,12}，真实K包含mandatory与阻塞扩展。小于|M|的选项不可选；全体不足K时使用实际人数。不同流量和同一流量的不同时刻都可选择不同K；不得直接按rate150/180固定两个K。

选择依据是可用时间、资源机会、耦合程度、紧迫对象及历史实际成本。不能假设高流量总该选择大K。成本评估必须包含选择器、候选、CP、验证及准备，公共服务另列并进入deadline余量。

C1先建立透明的规则规模控制：在{4,8,12}中，剔除依赖/必选不完整与预测时间不足的选项；根据当前明确阻塞与待服务机会需求选择能覆盖它们的最小规模，余项不足时回到8。无足够成本样本不把未知预测当安全许可，保留20秒协议并记录`COST_CALIBRATION_UNKNOWN`。

学习动态规模版在每个K最多提出2组，所有K合计最多6组，统一一次编码选择。**B只训练K=8，不能直接声称它能可靠比较K=4和12。**先在训练根补少量多K同状态标签，按同一新schema训练一次规模感知模型，再冻结。各K成本残差与期限失配单独报告，成本预测区间是经验估计而非最坏情况保证。

BALANCE式在线bandit是后续可选扩展，本版不强制加入。其奖励不能直接使用不同真实时刻之间的总着陆差作为某次K选择的因果收益；未观察的K没有反事实标签。

C1比较至少包括固定K8与规则自适应K；学习自适应还必须与规则自适应共用工厂、成本限制和后端。不得把改变K的收益全部归于网络。

### 10.2 C2：保持规模策略，独立研究20秒与10秒接入

默认保留20秒接入、5秒心跳、1秒prepare margin和4秒搜索交接预留。只有C1出现足够多完整任务、端到端可用时间支持较短窗口，且关键回归通过，才允许一次10秒配对试验。不自动扫描15/25/30等大量时间参数。

10秒下ready为9秒、搜索需在扣除4秒预留及已知服务占用后结束。该设置是试验点，不是部署承诺。必须在规划开始前确定接入点，重新预测相应未来状态和SOC，不能移动旧轨迹时间戳或以20秒训练数据自动豁免兼容性检查。

条件检查基于完整工作和交付延迟，不使用少量callback P95推导可执行性。仍可能因新交通、公共服务或不可中断验证错过窗口；这些结果如实保留。

C2只比较同一个规模策略在两种提前量下的结果，再比较同时间协议的规则与学习。正式报告把结构、学习、K和提前量四种贡献分开，不合并成一个无法解释的加速数字。

### 10.3 C的验收

检验K随状态而非只随流量变化；M不可被尺寸模型裁剪；规模变化不丢失背景需求；同一时刻的共同frame保持一致；成本预测不足不会延长期限；模型版本与future-state/lead一致。

闭环记录正常/应急/失败、待处理SOC与年龄、K分布、每秒CPU工作、每次准备/发布延迟、错失期限和接入率。若较短提前量降低了可用性或增加质量风险，保留20秒结果，不重试直到成功。

## 11. 时间预算与可执行接入：本合同不撤销已完成的延迟修复

A/B继承20/5/1/4秒时间协议，候选active上限6秒、CP累计上限8秒、hint上限3秒、soft30秒、watchdog60秒均是上限；实际受更早搜索和准备deadline限制。每机尝试32、全局1024，scope内所有扩展共享。不能因为选少飞机就把每机额度自动扩到全量总额度。

应满足：

\[
T_{selection}+T_{generation}+T_{CP}+T_{search\ validation}
+T_{final\ prep}+T_{revalidation}+Q_{service}+T_{delivery}<L-margin.
\]

未知未来服务不可能靠当前排队测量完全预知；固定预留只用于工程防护，不提供严格实时保证。仍需超时处理。

一项任务的搜素/补验不得重置时钟。搜索停止后交付已有认证incumbent，继续旧承诺直到未来授权时刻。结果逾期、依赖失效、准备后新冲突均不能免费补验。

同一个普通pending任务仍由现有协调器管理。A/B不新增多个并行CP任务、不解除全局提交锁。共同应急与准入的当前时间抽象保持并显式报告；未证明完整实机部署就绪。

规模减少但固定20秒生效时，速度收益首先是降低计算和超时，而不必立即增加吞吐。接入提前量改变必须留到C2，否则无法区分原因。

## 12. 有界算法流程

```text
1  在真实快照上开启完整在线计时，记录固定接入点与绝对期限。
2  沿既有权威承诺预测未来接入状态，不读取未来请求。
3  创建完整全局评价frame、背景续飞和廉价关系摘要。
4  建立共同mandatory集合及审查/进展年龄。
5  A:规则选S；B:至多6个同K集合一次打分；C:先排除不允许规模再一次选组。
6  构建scope。保留全世界，只开放S的动作变量。
7  复用S仍有效的候选；只为S生成新的多步候选。
8  局部CP及联合认证，保存第一份和每次改善的已认证incumbent。
9  若明确被未选正常飞机阻塞、存在剩余额度且尚未扩展：有界扩大S一次。
   重新验证受影响关系；不把旧scope证书直接迁移；最多12架。
10 搜索截止或无值得继续的工作时返回最好方案；有效WAIT允许返回。
11 现有执行层完成真实准备/必要补验/依赖核对；到点原子发布。
12 更新真实进展年龄；审查年龄只按真正完成的评估更新。
13 记录全部选择、计算、拒绝、接入及系统质量；下一任务从新快照开始。
```

回退不是“学习质量下降时自动知道并全量重算”。在线不知道遗漏了哪个更优解。只对可观测输入错误、无可用集合、明确阻塞、期限不足等触发确定性回退，质量遗漏通过离线比较和闭环发现。

## 13. 缓存、证书与检查点

缓存键至少区分物理配置、绝对时空轨迹、覆盖区间、当前能源账本、资源日历和scope依赖。只有能证明不变的部分复用。

几何证书可独立于无关SOC更新复用，但不能复用到不同轨迹或不同未覆盖时间段。单机能量可复用计划属性，当前剩余SOC必须重核。UNKNOWN/预算中断不可缓存成安全或不可行。

scope变化时，同一候选真实属性可复用；联合证明、prefix凭据与CP cut须检查依赖后再迁移。优先保守失效，不为追求命中率忽略真实变化。

checkpoint保存：pending时序、真实承诺、scope、年龄、子集策略状态、所有随机数状态、cost校准版本、模型指纹与数据血缘。恢复不得补记一个未发生的接入或重新执行已完成前缀；缓存可冷恢复，但测量说明冷/热状态。

## 14. 训练与运行公平性

1. FULL_H、规则局部、学习局部使用同一物理、资源、目标及时间协议；学习承担自己的所有特征与推理时间。
2. 比较B时旧逐候选学习排序关闭；所有局部组使用相同传统候选顺序与CP后端。
3. 同状态标签/计算对照使用相同缓存初态；可复制不可变缓存，各候选组不能免费继承之前组新算出的结果。
4. 闭环允许各自自然缓存，但报告预热和预计算，不伪造共同命中率。
5. 一对在线延迟实验同一物理核串行，固定数值线程与CP worker=1；记录版本、CPU占用和异常负载。独立离线标签可两核并行，成本标签来自固定独占核条件或标记不可比。
6. 已反复查看的seed和状态是开发集；新测试根在模型冻结后才运行。不同算法在同一个根分叉出来的轨迹属于同一祖先。
7. 只做单次小样本时不报告统计显著性、稳定P95或真实部署保证。
8. 不能通过少规划、少服务、早失败或不准入来伪造省电与加速；同时报告需求守恒、完成量和未完成负担。

## 15. 实验与资源边界

首轮自动计算总额度**10小时**，作为本合同新的开发上限，不重置任何历史ledger：A 2小时、B 5小时、C 2.5小时、归档0.5小时。编写代码和人工阅读不计入自动计算；实测数据采集、标签、训练、验证、失败运行均计入。独立阶段必须人工确认进入，不自动启动训练或全矩阵。

预算不足时输出`BUDGET_LIMITED`并保存共同已完成时间，不延长、不隐藏失败、不把未完成仿真记为物理失败。数据不足和算法负结果是合法产物。

默认开发回归沿用现有中等 `s3r23` / seed7324 与高流量 `s3r24` / seed7325原始输入，读取后验证hash，不改源文件。具体文件位置由现有root registry解析，不编造本地/服务器路径。

新训练/验证/测试seed区间在数据计划中固定，但创建前检查与已有root/manifest祖先冲突；冲突就跳过并选后续未占用seed，正式清单在采集前写定。输入模型保持，不能降低高流量或提高SOC改善学习数据。

A/B闭环先使用统一300秒观测窗口；未完成不算失败。C通过后可在**一组**代表性状态上追加“到达截止＋有限清空”诊断，最多追加300仿真秒，必须预算内且两方法相同，不把观察窗与清空结果混合。该扩展默认关闭，避免首轮规模膨胀。

## 16. 必须输出的证据

每任务保留：source/effective/deadline时间、eligible/selected/background/M、名义/实际K、所提集合、选择理由与模型分数、scope扩展、非选对象被生成候选次数（应为0）、决策/辅助变量数、验证配对类型、第一次非空认证与后续改进、搜索停止、准备、补验、服务排队、发布/拒绝。

输出三个不同的时钟：

- **正常规划工作**：选择器＋候选＋求解＋搜索验证＋最终准备/补验。
- **dispatch工作**：上述＋共同在线服务，按现有非重叠口径核算。
- **结果可用延迟**：从源快照到实际ready/发布的模拟时间，包含排队。

同时保留物理仿真、记录/渲染、离线审计成本，不能把它们冒充在线算法时间。小样本报告逐任务值与样本数，P95不作能力上限。

系统指标：正常/应急/失败/分流/未完成，初始与新到达分开；能耗及各环holding分项；review/progress age分位数与最大值；低余量积压；接入率/迟到率；每仿真秒CPU工作。补充候选/局部CP占用的实际硬件线程、第一次认证前缀与最后返回的差值，防止“只优化样本P95”掩盖累计成本。共享救援搜索耗时不等于应急架次。

回放沿用既有平台：明确标出选中组、固定背景、mandatory、阻塞关系、计划接入倒计时、已准备/拒绝状态。标注不改变物理轨迹。人工验收必须由真实观看产生，未看保持`HUMAN_PENDING`。

## 17. 验收结构：软件正确性与研究结论分开

同包`targeted_tests_v1_0.json`提供32项测试。正确性零容忍项为：遗漏背景安全、漏记能源/资源、改写已承诺轨迹、未来信息泄漏、过期执行、局部提交破坏联合依赖。出现任一项停止性能结论并修复。

效益报告采用以下状态，不强制“通过=算法获胜”：

| 状态 | 含义 |
|---|---|
| `IMPLEMENTED_CORRECTLY` | 定义和针对性检查已实现，尚未证明更快 |
| `STRUCTURAL_GAIN_OBSERVED` | A观察到真实规模与完整成本下降，质量边界已报告 |
| `LEARNING_GAIN_OBSERVED` | B相对相同局部规则方法观察到收益 |
| `TRADEOFF_OBSERVED` | 速度/质量存在明确代价，不能称无损加速 |
| `NO_GAIN_OBSERVED` | 当前试验没有建立优势 |
| `DATA_INSUFFICIENT` / `BUDGET_LIMITED` | 证据不足，不等于方法不可行 |

禁止因一次短试验无失败就宣称零失败保证；禁止因CP局部最优就宣称全局最优；禁止因A有效就宣称网络有效；禁止因C2较短提前量改善就归功于子集评分。

## 18. 阶段交付与代码提交顺序

**A提交顺序：**实际绑定与OFF回归 → scope/背景接口 →全局目标等价 →规则组与年龄/闭包 →局部认证与deadline →小情形 →同状态 →两类短闭环 →A结论。

**B提交顺序：**共同候选组工厂 →一次编码/新schema →新标签与血缘 →数据充分性报告 →一次fit →同预算离线 →两类短闭环 →B结论。

**C提交顺序：**多K覆盖/成本证据 →规则规模控制 →规模感知模型与同协议比较 →C1结论 →仅在条件满足时做10秒协议 →C2结论。

每一步更新对应文档和schema。禁止以超大提交同时改物理规则、目标和学习模型。分支中已有正确缓存和验证不得重复开发为第二套后端。

本合同不要求一次完成A/B/C。阶段门控制科学风险：A不能证明结构价值，就先交付A，不以“合同要求训练”强行启动B。

## 19. 已知局限与后续可选扩展

局部冻结可能使必要联合动作不可见；有界闭包和扩展只是缓解，不提供完备性。全局pad队列仍造成耦合，局部CP可能有O(N)辅助成本。固定20秒接入会限制速度收益向吞吐转化。公共服务可能仍主导延迟。模型有限样本可能只学到能源层，而非着陆机会。资源负荷不可持续时，任何选择器都无法承诺全体成功。

不在本版同时实现的扩展：多个普通规划任务并发、任意二进制子集策略、在线强化学习、学习末端价值、修改应急/准入、分布式通信、实机跟踪扰动、无限制全局LNS迭代。它们需要独立问题定义和证据，不作为本版获胜前提。

最终研究产物应能清楚回答：

> 减少的是哪些必须重算的对象？哪些全局约束仍然保留？学习比规则多贡献了什么？何时需要更大子问题？计算和提交期限怎样共同限制有效动作？
